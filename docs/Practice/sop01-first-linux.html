实验1：第一次进入 Linux

第一次进入 Linux，不需要背命令。本页只做四件事：认识 VMware 里的 CentOS、完成登录、看懂终端提示符、在目录之间走一圈，最后创建自己的第一个实验目录 LinuxLab。

本课目标 能启动并登录课程虚拟机；能使用 whoami、hostname、pwd、date、uname -a；能用 ls 查看、用 cd 切换目录；能查 man 和 --help；能创建 LinuxLab 并检查
项目阶段 环境热身。建立后续实验要用的主目录与基本操作习惯，本实验不涉及数据处理
练习方式 在 CentOS 课程虚拟机中亲手输入命令，截图留存结果，再按实验报告模板提交到雨课堂

1. 练习

1.1 认识实验环境

本课程不要求你在自己的电脑上安装 Linux。实验室电脑里已经准备好一台虚拟机，所有操作都在虚拟机中进行。

宿主机（实验室 Windows 电脑）
        ↓
VMware Workstation（虚拟机软件）
        ↓
CentOS 虚拟机（客户机系统，课程实验环境）
  • 宿主机：实验室里真实存在的 Windows 电脑，提供 CPU、内存和磁盘
  • 虚拟机软件：VMware Workstation，负责运行这台“虚拟电脑”
  • 客户机系统：课程提供的 CentOS，命令全部在这里执行
今天不要修改 CPU、内存、网络和虚拟磁盘设置，也不要移动、删除虚拟机文件。启动失败时先确认选中的是课程虚拟机，再举手说明报错信息，不要自己删掉重建。
检查点：能用自己的话说出“宿主机 → VMware Workstation → CentOS”三层关系，并指出哪一层是你真正操作的系统。

1.3 看懂终端提示符

终端里的提示符不是命令，它只是在告诉你“现在是谁、在哪台机器、在哪个目录”。本课程的提示符形如 [njucm@centos ~]$：方括号内是用户名、主机名和当前目录，$ 之后才是输入命令的位置。

whoami
# 输出：njucm
pwd
# 输出：/home/njucm
  • njucm：当前登录的用户名
  • centos：主机名示意，实际主机名以实验环境为准
  • ~：当前位于自己的主目录，即 /home/njucm
  • $：普通用户提示符；# 才是 root 用户
提示符本身不要复制进终端。只输入 whoami，不要输入整行 [njucm@centos ~]$ whoami，否则会得到 command not found。
检查点：能指出提示符中哪部分是用户名、哪部分是主机名、哪部分是当前目录标记。

1.4 认识“我”和“这台机器”

先回答五个最基本的问题：我是谁、机器叫什么、我在哪、现在几点、这是什么系统。五条命令逐条输入，执行一条看一次结果。

Step 1 / 逐条执行
whoami
hostname
pwd
date
uname -a
Step 2 / 参考输出（主机名与时间以实际环境为准）
njucm
centos
/home/njucm
2026年 11月 09日 星期一 10:23:45 CST
Linux centos 3.10.0-1160.el7.x86_64 #1 SMP x86_64 GNU/Linux
  • whoami：输出当前用户名，应为 njucm
  • hostname：输出主机名，不同实验机可能不同
  • pwd：输出当前目录的绝对路径
  • date：输出系统日期、时间与时区
  • uname -a：输出内核版本、主机名、硬件架构等系统信息
不要复制粘贴这五条命令。亲手敲一遍，才能发现自己容易拼错哪个单词。输出与同学不同并不可怕，先想清楚“主机名、时间”本来就允许不同。
检查点：能把每条命令的输出抄进实验记录，并各用一句话说明它回答了什么。

1.5 用 ls 查看目录

同一个目录，用不同参数会看到不同信息。先确认位置，再逐条比较差别。

Step 1 / 同一目录，五种看法
pwd
ls
ls -l
ls -a
ls -la
命令显示内容适合什么时候用
ls只显示名称，按列排列快速确认这里有什么
ls -l长格式：权限、所有者、大小、修改时间查看文件类型与属性
ls -a连以 . 开头的隐藏文件一起显示检查配置文件、隐藏目录
ls -la长格式 + 隐藏文件实验中最常用的检查方式
Step 2 / 观察任务
  • 哪一条命令显示的信息最多？多了哪些列？
  • ls -a 之后是否多出以 . 开头的项目？至少找到 . 和 ..
  • 你的主目录里有哪些文件夹？哪些是你认识的？
Linux 区分大小写。ls 与 LS 不是同一条命令。输入 clear 可以清屏，然后按 pwd → ls → ls -l → ls -a 再做一遍。
检查点：能说出 -l 与 -a 各自补充了什么信息，并能指出隐藏文件的判断依据。

1.6 用 cd 走一圈

每切换一次目录，都用 pwd 确认当前位置。不要凭感觉认为自己“应该到了”。

Step 1 / 按路线切换
cd /
pwd
ls
cd /home
pwd
ls
cd /tmp
pwd
ls
cd ~
pwd
Step 2 / 预期位置
/              根目录，整个文件系统的起点
/home          普通用户主目录的集合
/tmp           临时目录，重启后内容可能被清理
/home/njucm    回到自己的主目录，也可写作 ~
  • cd / 后 pwd 应输出 /
  • cd /home 后应输出 /home
  • cd /tmp 后应输出 /tmp
  • cd ~ 后应输出 /home/njucm
cd 后面不写参数也会回到主目录；cd - 可以回到上一次所在目录。今天先把 cd ~ 用熟。
检查点：不看本页路线，自己完成 / → /home → /tmp → ~，每到一个位置都执行 pwd。

1.7 man 与 --help

不会的命令不要猜。Linux 自带说明书：man 查看完整手册，命令 --help 查看常用选项，Tab 键可以减少拼写错误。

Step 1 / 打开两本“说明书”
man ls
# 按 q 退出 man
ls --help
man mkdir
# 按 q 退出 man
mkdir --help
Step 2 / 用 Tab 补全路径
cd /ho
# 输入到 /ho 后按 Tab，观察是否补全为 /home
# 再输入 cd /home/nju，按 Tab 观察是否补全为 njucm
  • 查出 ls -a 中 -a 的含义
  • 查出 ls -l 中 -l 的含义
  • 用 mkdir --help 找出创建多级目录的参数
  • 用 Tab 补全 /ho 后面的路径
man 界面里用方向键或 PageUp / PageDown 翻页，按 q 退出。退不出来时先按 q，不要直接关终端。
检查点：能独立查到 -a、-l 的含义，并知道 mkdir -p 的作用。

1.8 创建 LinuxLab

这一次完全照着教程敲：回到主目录，创建 LinuxLab，再创建三个子目录和一个说明文件。

Step 1 / 逐条执行
cd ~

cd LinuxLab
mkdir data
mkdir script
mkdir result

ls -la
Step 2 / 目标结构
LinuxLab/
├── data/
├── script/

做完先不要关终端。确认 LinuxLab 中确实有 data、script、result 三个子目录和 README.txt，再截图。
检查点：pwd 显示 /home/njucm/LinuxLab；ls -la 中四个目标项齐全，且没有拼写错误。

1.10 常见错误与常见问题

报错不是失败，而是系统在告诉你哪里不对。先读报错文字，再检查位置、内容和拼写，最后才改命令。

报错常见原因先做什么
No such file or directory路径或文件名写错，或目标不存在pwd 看位置，ls 看拼写
command not found命令拼错、大小写错误或不存在检查 ls 是否写成了 LS
Permission denied当前用户没有权限先确认对象，不要一看到就加 sudo
Is a directory把目录当作普通文件操作ls -l 看对象类型
File existsmkdir 的目标已经存在ls 确认后进入或用其他名字
排错口诀：先看报错文字 → 再用 pwd 看位置 → 再用 ls 看内容 → 检查大小写和拼写 → 最后查帮助。
  • 问题：提示符里的 ~ 是不是命令？——不是，它只是当前目录标记
  • 问题：为什么 cd ~ 之后 pwd 不是 ~？——pwd 显示真实绝对路径
  • 问题：ls -la 里的 . 和 .. 是什么？——当前目录与上一级目录
  • 问题：命令输出和同学不一样怎么办？——主机名、时间允许不同，先核对命令本身
检查点：遇到报错时，能按口诀完成一次自查，并说出报错对应的原因。
