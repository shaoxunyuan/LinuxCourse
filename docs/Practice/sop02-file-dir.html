实验2：文件与目录管理

上一节只要求你会看目录，这一节要求你能动手整理目录。本页从路径判断开始，依次练习创建、复制、移动、改名和删除，最后在 ~/LinuxProject 中独立整理出一套结构清楚、可以检查的项目目录。

本课目标 能说清绝对路径与相对路径；能用 mkdir、touch、file、stat、cp、mv、rm、rmdir 完成文件与目录操作；能先用 ls 确认再动手
项目阶段 目录整理。在课程练习数据 ~/LinuxProject 中建立工作目录，把文件分类放好并完成备份
练习方式 在 CentOS 课程虚拟机中亲手输入命令，截图留存结果，再按实验报告模板提交到雨课堂

1. 练习

1.1 先想清四个问题

文件管理看起来很杂，其实每次操作前只回答四个问题：我在哪里、这里有什么、目标在哪里、我要做什么。前两个问题用命令回答，后两个问题靠路径和对命令的理解回答。

Step 1 / 先确认练习数据在不在
cd ~/LinuxProject
pwd
ls
  • 我现在在哪里：用 pwd 看当前绝对路径
  • 这里有什么：用 ls 看当前目录内容
  • 目标在哪里：用绝对路径或相对路径描述目标
  • 我要做什么：创建、复制、移动、改名还是删除
本节所有操作都建立在 ~/LinuxProject 上。如果 pwd 或 ls 报 No such file or directory，先回到主目录执行 bash create_linux_practice_data.sh，不要在错误路径上继续操作。
检查点：pwd 显示 /home/njucm/LinuxProject，ls 至少能看到 README.txt 与 data、logs、docs 等目录。

1.2 绝对路径与相对路径

绝对路径从根目录 / 写起，位置唯一；相对路径从当前目录写起，更短，但换个位置就可能失效。四个符号先记牢：~ 是主目录，. 是当前目录，.. 是上一级目录，/ 是根目录。

写法示例从哪算起特点
绝对路径/home/njucm/LinuxProject/data根目录 /完整、唯一，不受当前位置影响
相对路径data/patients当前目录简短，但必须先确认 pwd
~~/LinuxProject当前用户主目录展开为 /home/njucm
../README.txt当前目录强调“就在当前目录里”
..../docs上一级目录从子目录返回父目录
//home文件系统起点所有绝对路径的开头
Step 1 / 用现有目录走一遍
cd ~/LinuxProject
pwd
pwd -P
cd data
pwd
cd ..
pwd
cd ./data/patients
pwd
cd ../..
pwd
cd ~/LinuxProject/docs/notes
pwd
cd ~
pwd
Step 2 / 预期位置
# cd ~/LinuxProject 之后      → /home/njucm/LinuxProject
# cd data 之后                 → /home/njucm/LinuxProject/data
# cd .. 之后                   → /home/njucm/LinuxProject
# cd ./data/patients 之后      → /home/njucm/LinuxProject/data/patients
# cd ../.. 之后                → /home/njucm/LinuxProject
# cd ~/LinuxProject/docs/notes → /home/njucm/LinuxProject/docs/notes
# cd ~ 之后                    → /home/njucm
  • 每执行一次 cd，紧接着执行一次 pwd，不要凭感觉判断位置
  • 观察 cd .. 与 cd ../.. 分别回到哪一层
  • 观察 cd ~ 和 cd ~/LinuxProject 的区别
~/LinuxProject 是数据脚本建立的符号链接，指向桌面上的 LinuxProject。所以 pwd 可能显示 /home/njucm/LinuxProject，而 pwd -P 显示真实的桌面路径；两种显示都不是错误。
检查点：能说出每个 pwd 输出为什么是这个路径，并能用 .. 从 data/patients 一次回到 LinuxProject。

1.3 建立练习目录骨架

先把“文件柜”搭好。所有练习都放在 ~/LinuxProject/filelab，不要直接改动课程原始数据目录。用 mkdir -p 一次建立多级目录，已经存在的目录不会报错。

Step 1 / 创建 filelab 结构
cd ~/LinuxProject
mkdir -p filelab/data/raw filelab/data/processed filelab/scripts filelab/results filelab/docs filelab/backup
cd filelab
pwd
ls -R
Step 2 / 目标结构
filelab/
├── data/
│   ├── raw/
│   └── processed/
├── scripts/
├── results/
├── docs/
└── backup/
  • pwd 应输出 /home/njucm/LinuxProject/filelab
  • ls -R 应能看到 data/raw、data/processed 两级目录
  • scripts、results、docs、backup 四个目录都存在
如果只写 mkdir filelab/data/raw，而 filelab/data 还不存在，就会报 No such file or directory。-p 的作用是“缺哪层补哪层”，并且目标已存在时也不报错。
检查点：ls -R 的层级与目标结构一致，且没有任何一个目录名拼错。

1.4 创建文件并查看信息

touch 创建空文件；file 根据内容判断类型；stat 查看大小、权限和三个时间。三个命令回答的是不同问题，不要混用。

Step 1 / 创建练习文件
cd ~/LinuxProject/filelab
touch README.txt
touch sample1.txt sample2.txt sample3.txt
touch analysis.py plot.py
touch result1.csv result2.csv
touch notes.txt temp.txt
touch sample10.txt
ls -l
Step 2 / 查看文件本身的信息
file README.txt
stat README.txt
# ls -l 中新建空文件的大小为 0
# file README.txt 的输出为：README.txt: empty
# stat README.txt 中 Size: 0，并列出 Access、Modify、Change 三个时间
  • 数一数 ls -l 每行第 1 个字符是什么，代表文件类型
  • 比较 ls -l 与 stat 显示的信息差别
  • 用 file 判断一个文件是不是“只看扩展名”就能确定类型
touch 对已存在的文件不会清空内容，只会更新访问和修改时间。file 看的是文件内容，不是扩展名；把 .csv 改成 .txt 并不会改变它的真实类型。
检查点：能指出新建空文件大小为 0，能读出 file 与 stat 各自给出的关键信息。

1.5 复制文件与目录

cp 的关键是分清“源”和“目标”。复制文件后原文件仍然保留；复制目录必须加 -r，否则只会得到一个“不能复制目录”的报错。

Step 1 / 复制文件与目录
cd ~/LinuxProject/filelab
cp README.txt README_copy.txt
cp README.txt backup/
cp -i README.txt backup/
# 目标 backup/README.txt 已存在，按提示输入 y 覆盖
cp sample1.txt backup/
cp -r data backup/data_copy
cp ~/LinuxProject/config/hospital.conf backup/hospital.conf.bak
ls -R backup
Step 2 / 验证
  • 根目录的 README.txt 是否还在
  • backup 中是否出现了 README.txt、sample1.txt、hospital.conf.bak
  • backup/data_copy 中是否有 raw 与 processed 两个子目录
  • cp -i 在什么情况下才会询问
cp 源 目标 中，如果目标是已存在的目录，文件会被复制进去；如果目标是新名字，则相当于复制并改名。覆盖已有文件前先用 ls 看清目标，需要确认时加 -i。
检查点：原文件仍在，backup 中能看到副本，且能解释复制目录为什么必须加 -r。

1.6 移动与重命名

mv 既能“搬家”也能“改名”。移动成功后，源位置通常就没有它了，这一点与 cp 完全不同。

Step 1 / 改名与移动
cd ~/LinuxProject/filelab
mv README.txt README_Linux.txt
mv notes.txt docs/
mv analysis.py plot.py scripts/
mv result1.csv result2.csv results/
mv README_copy.txt docs/README_copy.txt
mv backup/hospital.conf.bak backup/hospital_config.bak
ls -R
Step 2 / 检查源与目标
  • 根目录是否还存在 README.txt
  • scripts 中是否有 analysis.py 与 plot.py
  • results 中是否有两个 .csv 文件
  • docs 中是否出现了 notes.txt 与 README_copy.txt
mv 的目标是已存在目录时，会把源移动进去；目标是新文件名时，相当于改名。目标位置已有同名文件时可能直接覆盖，重要文件先用 ls 确认，必要时使用 mv -i。
检查点：每个文件只在预期位置出现一次，源位置没有残留副本。

1.7 安全删除文件与目录

Linux 终端没有 Windows 那样的回收站，删除前要先看位置、再看对象、最后才执行。rmdir 只能删除空目录，目录里还有内容时会失败。

Step 1 / 删文件前先确认
cd ~/LinuxProject/filelab
pwd
ls -l temp.txt
rm -i temp.txt
# 提示 remove regular empty file 'temp.txt'? 时输入 y
Step 2 / 删除空目录与非空目录
mkdir emptydir
rmdir emptydir
mkdir trash_demo
touch trash_demo/a.txt trash_demo/b.txt
ls -R trash_demo
rm -r trash_demo
rmdir backup/data_copy
# 预期报错：Directory not empty
rm -r backup/data_copy
ls -R backup
  • rmdir emptydir 成功，因为目录是空的
  • rmdir backup/data_copy 失败，因为里面还有子目录
  • rm -r 只用于已经用 ls -R 确认过的目录
  • rm -i 每删一个对象都会询问，适合新手
不要把 rm -rf 当作常规删除方法。路径没看清、通配符范围没确认时，不要执行带 -r 或 -f 的删除命令；先 pwd，再 ls，最后删。
检查点：temp.txt 已删除；能解释 rmdir 与 rm -r 的适用场景，并完成过一次 pwd → ls → rm -i 的安全删除流程。

1.8 用通配符批量操作

文件多起来以后，用通配符一次匹配多个对象。规则很简单：* 匹配任意多个字符，? 只匹配一个字符。批量操作前先用 ls 验证匹配范围。

通配符匹配范围本节示例
*.txt所有以 .txt 结尾的文件README.txt、notes.txt
sample*.txtsample 开头、.txt 结尾，中间可以是任意多个字符sample1.txt、sample10.txt
sample?.txtsample 后只允许一个字符sample1.txt 到 sample3.txt
results/*.csvresults 目录下所有 .csvresult1.csv、result2.csv
Step 1 / 先看匹配，再批量移动
cd ~/LinuxProject/filelab
ls sample*.txt
# 预期：sample1.txt sample2.txt sample3.txt sample10.txt
ls sample?.txt
# 预期：sample1.txt sample2.txt sample3.txt
rm -i sample10.txt
mv sample*.txt data/raw/
ls data/raw/
Step 2 / 批量复制结果文件
ls results/*.csv
cp results/*.csv backup/
ls backup/
通配符由 shell 先展开成具体文件名，再交给命令执行。执行 mv、cp、rm 之前，先单独执行一次同样的通配符给 ls，确认它到底匹配了哪些文件。
检查点：能预测 sample*.txt 与 sample?.txt 各自匹配几个文件，并在批量操作后用 ls 验证结果。

1.9 用 ls 检查整理结果

命令没有报错，不代表结果一定正确。文件操作做完后必须检查：名称对不对、位置对不对、数量对不对。

命令显示内容本实验用它检查什么
ls当前目录的名称列表快速确认这里有什么
ls -l权限、所有者、大小、修改时间确认文件类型与大小
ls -a包含以 . 开头的隐藏项确认没有遗漏隐藏文件
ls -lh文件大小换成 KB、MB 等易读单位比较备份文件大小
ls -lt按修改时间从新到旧排序确认最近操作了哪些文件
ls -R递归列出所有子目录检查整个项目结构
Step 1 / 逐项检查
cd ~/LinuxProject/filelab
pwd
ls
ls -lh
ls -lt
ls -la
ls -R
Step 2 / 对照结构自查
filelab/
├── README_Linux.txt
├── data/
│   ├── raw/            # sample1.txt sample2.txt sample3.txt
│   └── processed/
├── scripts/            # analysis.py plot.py
├── results/            # result1.csv result2.csv
├── docs/               # notes.txt README_copy.txt
└── backup/             # README.txt sample1.txt hospital_config.bak result1.csv result2.csv
发现位置不对时，不要继续往下复制或删除。先用 pwd 确认自己在哪，再用 ls -R 找到文件实际在哪里，最后决定是移动回来还是重新操作。
检查点：能对照结构图指出每个文件应在的目录，并用 ls -R 证明它确实在那里。

1.10 常见报错与排错

报错信息通常已经说明了问题。先读报错原文，再检查当前位置和对象，不要一看到失败就换一条更危险的命令。

报错常见原因先做什么
No such file or directory路径或文件名写错，或目标不存在pwd 看位置，ls 看拼写
cannot statcp 或 mv 找不到源文件确认源文件存在，并核对当前目录
Directory not emptyrmdir 的目标目录里还有内容ls -R 看清内容后再决定如何删除
cannot overwrite directory文件与目录类型不匹配，路径写混了ls -ld 分别查看源和目标
Permission denied当前用户没有对应权限先确认对象和权限，不要直接加 sudo
排错口诀：先看报错文字 → 再用 pwd 看当前位置 → 再用 ls 看目录内容 → 检查大小写和拼写 → 最后查帮助。ls 与 LS、filelab 与 FileLab 都不是同一个名字。
  • 问题：cp: cannot stat 'sample1.txt' 说明什么？——当前目录没有这个文件，先 pwd
  • 问题：rmdir 为什么删不掉 backup/data_copy？——它不是空目录
  • 问题：mv 后源文件去哪了？——已经到目标位置，源位置不再保留
  • 问题：通配符匹配结果不确定怎么办？——先执行 ls 通配符 验证
检查点：能按口诀完成一次自查，并把报错原文、原因和改正命令写进实验记录。
