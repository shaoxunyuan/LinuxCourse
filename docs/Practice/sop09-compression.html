实验9：文件压缩与解压

文件太多时，先把它们打包成一个归档；文件太大时，再压缩减少体积。本节从 tar 的打包与查看开始，依次加入 gzip 和 ZIP，最后对 ~/LinuxProject 做一次可验证的备份与恢复。

本课目标 能区分打包与压缩；能用 tar、gzip、zip 创建归档和压缩包；能查看归档内容、解压到指定目录并核对结果
项目阶段 数据归档与备份。用 ~/ArchiveLab 练习三种格式，再备份 ~/LinuxProject 并验证恢复完整
练习方式 在 CentOS 课程虚拟机中亲手输入命令，截图留存结果，再按实验报告模板提交到雨课堂

1. 练习

1.1 打包与压缩的区别

打包解决“文件太多、太分散”的问题，把多个文件放进一个归档文件；压缩解决“体积太大”的问题，用算法减少数据占用的空间。两件事可以分开做，也可以一次完成。

Step 1 / 先做一次只打包、不压缩的实验
cd ~
mkdir -p pack_demo
cd pack_demo
printf 'one\n' > a.txt
printf 'two\n' > b.txt
ls -l a.txt b.txt
tar -cvf two.tar a.txt b.txt
ls -l a.txt b.txt two.tar
tar -tvf two.tar

预期输出（大小示意，具体数值以你的终端为准）：

-rw-r--r-- 1 njucm njucm     4 a.txt
-rw-r--r-- 1 njucm njucm     4 b.txt
-rw-r--r-- 1 njucm njucm 10240 two.tar
a.txt
b.txt
Step 2 / 再对归档文件做一次压缩
gzip -c two.tar > two.tar.gz
ls -l two.tar two.tar.gz
  • 两个 4 字节的小文件打包后为什么变成 10240 字节？
  • .tar 与 .tar.gz 的扩展名分别说明了什么？
  • 打包之后，原始文件 a.txt、b.txt 是否还在？
tar 只负责把文件组织到一起，不加 -z 时不会压缩数据。小文件打包后甚至可能变大，这是归档块大小带来的正常现象。
检查点：能用自己的话说出“打包是合并文件，压缩是减小体积”，并能指出 .tar 不一定比原文件小。

cd ~

1.3 tar 打包、查看与解包

三个参数各管一件事：-c 创建归档，-v 显示处理过程，-f 后面紧跟归档文件名。查看归档用 -t，解包用 -x；-C 指定解压目标目录。

Step 1 / 打包整个目录，并核对前后变化
cd ~
ls -ld ArchiveLab
tar -cvf ArchiveLab.tar ArchiveLab/
ls -lh ArchiveLab.tar
ls -ld ArchiveLab
Step 2 / 不解压也能查看归档清单
tar -tvf ArchiveLab.tar

预期输出（权限、时间和大小以实际为准）：

drwxr-xr-x njucm/njucm      0 2026-11-09 09:00 ArchiveLab/
-rw-r--r-- njucm/njucm     40 2026-11-09 09:00 ArchiveLab/README.txt
-rw-r--r-- njucm/njucm 150000 2026-11-09 09:00 ArchiveLab/app.log
drwxr-xr-x njucm/njucm      0 2026-11-09 09:00 ArchiveLab/data/
-rw-r--r-- njucm/njucm     70 2026-11-09 09:00 ArchiveLab/data/notes.txt
-rw-r--r-- njucm/njucm     56 2026-11-09 09:00 ArchiveLab/students.txt
Step 3 / 解包到单独目录并核对
mkdir -p restore_tar
tar -xvf ArchiveLab.tar -C restore_tar
find restore_tar -type f | sort
diff -r ArchiveLab restore_tar/ArchiveLab && echo "tar 恢复：内容一致"
ls -lh restore_tar/ArchiveLab
  • -t 只列清单，会不会修改原始目录或归档？
  • 归档中的路径为什么都以 ArchiveLab/ 开头？
  • 解压后为什么是 restore_tar/ArchiveLab/...，多了一层？
打包前先用 pwd 和 ls 确认当前位置与源目录名。如果当前目录不是 ~，ArchiveLab/ 就会找不到，tar 会报 Cannot open 或 No such file or directory。
检查点：ArchiveLab.tar 创建成功，tar -tvf 能看到 4 个普通文件和 data/ 目录，原始目录仍然存在，diff -r 无差异。

1.4 tar.gz 压缩与解压

-z 在打包的同时调用 gzip 压缩，产物通常写成 .tar.gz 或 .tgz。原始目录仍然保留，解压时同样要加 -z。

Step 1 / 创建 tar.gz，并与 tar 比较大小
cd ~
tar -czvf ArchiveLab.tar.gz ArchiveLab/
ls -lh ArchiveLab.tar ArchiveLab.tar.gz
tar -tzvf ArchiveLab.tar.gz | head -n 5

预期输出（数值示意）：

-rw-r--r-- 1 njucm njucm 151K ArchiveLab.tar
-rw-r--r-- 1 njucm njucm 6.2K ArchiveLab.tar.gz
Step 2 / 解压到 restore_gz 并核对文件数量
mkdir -p restore_gz
tar -xzvf ArchiveLab.tar.gz -C restore_gz
find restore_gz -type f | wc -l
diff -r ArchiveLab restore_gz/ArchiveLab && echo "gz 恢复：内容一致"
  • app.log 内容高度重复，为什么压缩效果特别明显？
  • -z 在创建和解压两侧分别起什么作用？
  • 如果文件本身是随机二进制数据，还能有这么高的压缩比吗？
压缩比取决于文件内容，不是固定值。已经压缩过的图片、视频再打包成 .tar.gz，体积可能几乎不减少。
检查点：ArchiveLab.tar.gz 明显小于 ArchiveLab.tar；tar -tzvf 能列出清单；解压后文件数量与原始目录一致，diff -r 无差异。

1.5 gzip 与 gunzip

gzip 只处理单个文件。默认行为是生成 .gz 并删除原文件；想保留原文件时用 -k，或者用 -c 把压缩结果写到标准输出。

Step 1 / 压缩单个文件，观察原文件是否消失
cd ~/ArchiveLab
cp README.txt README.copy.txt
ls -l README*
gzip README.copy.txt
ls -l README*

预期输出：

-rw-r--r-- 1 njucm njucm 40 README.txt
-rw-r--r-- 1 njucm njucm 40 README.copy.txt
-rw-r--r-- 1 njucm njucm 40 README.txt
-rw-r--r-- 1 njucm njucm 66 README.copy.txt.gz
Step 2 / 解压 .gz 并验证内容
gunzip README.copy.txt.gz
ls -l README*
diff README.txt README.copy.txt && echo "gunzip 恢复：内容一致"
Step 3 / 保留原文件的两种写法
gzip -k app.log
ls -lh app.log app.log.gz

gzip -c app.log > app_copy.log.gz
ls -lh app.log app_copy.log.gz
Step 4 / 验证 gzip 不能直接压缩目录
gzip data
echo $?

预期输出（退出码通常为非 0，说明命令没有处理成功）：

gzip: data is a directory -- ignored
2
  • gzip README.copy.txt 之后原文件为什么不见了？
  • gzip -k 与 gzip -c ... > ... 都能保留原文件，区别是什么？
  • 目录要压缩，应该先做什么？
目录不能直接被 gzip 压缩。正确做法是先用 tar 打包，再对归档文件做 gzip，这正是 tar -z 存在的原因。
检查点：能看到 .gz 生成、原文件消失；gunzip 后内容与 README.txt 一致；gzip data 提示目录被忽略。

1.6 zip、unzip 与格式对照

ZIP 是与 Windows 交换文件时最常用的格式。压缩目录必须加 -r 递归；查看清单用 unzip -l；指定解压目录用 -d。

Step 1 / 创建 ZIP，查看内容并解压
cd ~
rpm -q zip unzip
zip -r ArchiveLab.zip ArchiveLab/
ls -lh ArchiveLab.zip
unzip -l ArchiveLab.zip

预期输出（节选并省略目录项，长度与时间以实际为准；此时目录中已有 1.5 生成的 .gz 文件，因此共 7 个普通文件）：

  Length      Date    Time    Name
---------  ---------- -----   ----
       40  11-09-2026 09:00   ArchiveLab/README.txt
       40  11-09-2026 09:00   ArchiveLab/README.copy.txt
   138000  11-09-2026 09:00   ArchiveLab/app.log
     4600  11-09-2026 09:00   ArchiveLab/app.log.gz
     4600  11-09-2026 09:00   ArchiveLab/app_copy.log.gz
       70  11-09-2026 09:00   ArchiveLab/data/notes.txt
       56  11-09-2026 09:00   ArchiveLab/students.txt
---------                     -------
   147406                     7 files
Step 2 / 解压到 restore_zip 并核对
mkdir -p restore_zip
unzip ArchiveLab.zip -d restore_zip
find restore_zip -type f | sort
diff -r ArchiveLab restore_zip/ArchiveLab && echo "ZIP 恢复：内容一致"
Step 3 / 常见压缩格式对照
格式创建命令查看内容解压 / 恢复是否压缩典型用途
.tartar -cvf x.tar dir/tar -tvf x.tartar -xvf x.tar -C out/否，只打包先归档，再选择压缩方式
.tar.gztar -czvf x.tar.gz dir/tar -tzvf x.tar.gztar -xzvf x.tar.gz -C out/是，gzipLinux 备份与传输的常用格式
.gzgzip -k filezcat file.gzgunzip file.gz是，gzip单个文件压缩，不能直接压缩目录
.zipzip -r x.zip dir/unzip -l x.zipunzip x.zip -d out/是与 Windows 用户交换文件
  • 不加 -r 时，ZIP 包里会缺少什么？
  • unzip -l 与 tar -tvf 的作用是否相似？
  • 同样一个目录，.tar.gz 与 .zip 的大小为什么不一样？
如果 zip 或 unzip 显示 command not found，先举手说明，不要自行修改系统软件源。课程虚拟机上这两个工具通常已经安装，可以用 rpm -q zip unzip 确认。
检查点：unzip -l 列出 7 个普通文件；unzip -d 后 diff -r 无差异；能对照表格说清四种格式的创建与查看命令。

Step 1 / 从真实目录的上级目录打包
cd ~
cd "$(dirname "$(readlink -f LinuxProject)")"
pwd

Step 2 / 解压到独立目录并核对
mkdir -p ~/ArchiveLab/verify
tar -xzvf ~/ArchiveLab/LinuxProject-$STAMP.tar.gz -C ~/ArchiveLab/verify

diff -r ~/LinuxProject ~/ArchiveLab/verify/LinuxProject && echo "备份恢复：内容一致"
~/LinuxProject 是指向桌面真实目录的符号链接。直接打包符号链接只会得到一个指向原路径的链接，不会包含文件内容；所以先用 readlink -f 找到真实目录，再在它的上级目录执行 tar。
