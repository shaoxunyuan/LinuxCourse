实验10：系统信息与进程管理

程序在运行吗？谁占用了 CPU 和内存？磁盘还够不够？本节用一组系统命令回答这些问题：先看系统与进程，再找到并结束自己启动的测试进程，最后检查内存和磁盘空间。

本课目标 能查看系统基本信息；用 ps、top 观察进程；理解 PID；用 pgrep 定位、用 kill 结束自己启动的测试进程；用 free、df、du 查看资源
项目阶段 系统运行状态检查。围绕当前 CentOS 会话完成进程查看、测试进程管理和资源核对
练习方式 在 CentOS 课程虚拟机中亲手输入命令，截图留存结果，再按实验报告模板提交到雨课堂

1. 练习

1.1 查看系统基本信息

先回答“我是谁、在哪台机器上、系统运行了多久”。这几条命令都很短，但输出里的每一段都对应一个具体信息。

Step 1 / 逐条执行系统信息命令
whoami
hostname
uname -a
uptime
date

预期输出（主机名、内核版本和时间以实际为准）：

njucm
centos
Linux centos 3.10.0-1160.el7.x86_64 #1 SMP Mon Oct 19 16:18:59 UTC 2020 x86_64 x86_64 x86_64 GNU/Linux
 10:23:41 up  2:15,  1 user,  load average: 0.00, 0.01, 0.05
Mon Nov  9 10:23:41 CST 2026
  • uname -a 输出中哪一段是内核版本？哪一段是 CPU 架构？
  • uptime 的 load average 三个数字分别代表最近 1、5、15 分钟的平均负载
  • date 显示的时区是什么？和你的实际时间一致吗？
uname -a 一次显示内核名、主机名、内核版本、编译信息和硬件架构。uname -r 只显示内核版本，信息更简洁。
检查点：能读出当前用户名、主机名、内核版本、系统已运行时长和当前时间。

1.2 ps 查看进程

进程是正在运行的程序实例，每个进程都有一个 PID。ps 显示的是执行命令那一刻的进程快照，不会持续刷新。

Step 1 / 先看当前终端相关进程，再看完整列表
ps
ps aux | head
ps -ef | head

预期输出（节选，PID 与时间以实际为准）：

  PID TTY          TIME CMD
 2318 pts/0    00:00:00 bash
 2450 pts/0    00:00:00 ps

USER   PID %CPU %MEM    VSZ   RSS TTY      STAT START   TIME COMMAND
root     1  0.1  0.4 128164  6804 ?        Ss   08:00   0:04 /usr/lib/systemd/systemd --switched-root --system
root     2  0.0  0.0      0     0 ?        S    08:00   0:00 [kthreadd]

UID        PID  PPID  C STIME TTY          TIME CMD
root         1     0  0 08:00 ?        00:00:04 /usr/lib/systemd/systemd --switched-root --system
root         2     0  0 08:00 ?        00:00:00 [kthreadd]
Step 2 / 用 grep 定位指定进程
ps -ef | grep '[b]ash'
ps -ef | grep '[s]shd'
  • PID 位于输出的第几列？CMD 列表示什么？
  • ps -ef 比 ps 多了哪些列？PPID 有什么含义？
  • 为什么写成 [b]ash 而不是直接写 bash？
grep bash 会把 grep 自己的命令行也匹配进去；写成 grep '[b]ash' 可以避免这一类“假结果”。ps aux 关注资源占用，ps -ef 关注父子进程关系。
检查点：能从 ps 输出中指出 PID 列，并找到当前终端里运行的 bash 进程。

1.3 top 动态观察

top 是交互式界面，会持续刷新 CPU、内存和进程列表。进入后先看顶部汇总，再看下面占资源较多的进程。

Step 1 / 进入 top，观察并按需排序
top

# 进入后：
# 按 P  —— 按 CPU 使用率排序
# 按 M  —— 按内存使用率排序
# 按 q  —— 退出 top

顶部汇总示意（CentOS 7 的 top 默认以 KiB 显示，数值随机器变化）：

top - 10:30:12 up  2:21,  1 user,  load average: 0.00, 0.01, 0.05
Tasks: 121 total,   1 running, 120 sleeping,   0 stopped,   0 zombie
%Cpu(s):  0.3 us,  0.2 sy,  0.0 ni, 99.3 id,  0.1 wa,  0.0 hi,  0.1 si,  0.0 st
KiB Mem :  1865460 total,  1233452 free,    184598 used,    447410 buff/cache
KiB Swap:  2097148 total,  2097148 free,         0 used
  • 顶部第一行显示了哪些信息？
  • 按 P 后列表排序依据是什么？按 M 后又变成什么？
  • 退出 top 应该按哪个键？
top 是交互界面，优先按 q 退出，不要在学生机上直接关闭终端窗口。界面里的 %Cpu(s) 和 KiB Mem 会随时间不断变化。
检查点：能进入 top、用 P 和 M 改变排序、再用 q 正常退出，并说出顶部三行各显示什么。

1.4 pgrep、kill 与 kill -9

本练习只操作自己启动的 sleep 测试进程。先用 sleep 300 & 在后台启动一个“什么都不做、只等待”的进程，再找到它的 PID 并结束它。

Step 1 / 启动测试进程并取得 PID
sleep 300 &
PID=$!
echo $PID
ps -p $PID -o pid,ppid,stat,cmd

预期输出（PID 以实际为准）：

[1] 2456
2456
  PID  PPID STAT CMD
 2456  2318 S    sleep 300
Step 2 / 用 pgrep 和 ps 交叉确认
pgrep -a -x sleep
ps -ef | grep '[s]leep 300'

预期输出（如果还有别的 sleep 练习进程，可能看到多行）：

2456 sleep 300
njucm  2456  2318  0 10:30 pts/0  00:00:00 sleep 300
Step 3 / 先正常结束，再验证进程已经消失
kill $PID
ps -p $PID
echo $?

预期输出（没有找到进程时只打印表头，退出码为 1）：

  PID TTY          TIME CMD
1
Step 4 / 再启动一个测试进程，了解强制结束
sleep 300 &
PID2=$!
kill -9 $PID2
ps -p $PID2
echo $?
  • echo $! 和 echo $PID 显示的是什么？为什么 PID 要保存到变量里？
  • kill $PID 与 kill -9 $PID 有什么区别？
  • ps -p $PID 只打印表头并返回 1，说明什么？
不要随意 kill 系统进程。默认的 kill 发送 -15（SIGTERM），请求进程正常退出并有机会清理；kill -9（SIGKILL）强制结束，进程来不及保存或清理。只对本次练习中自己启动的 sleep 进程使用，PID 不确定时先用 ps -p 确认。
拓展提示（nice / renice）：nice 值范围是 -20 到 19，数值越大优先级越低。可以用 nice -n 10 sleep 300 & 以较低优先级启动进程，用 renice -n 15 -p PID 调整已有进程。普通用户通常只能把 nice 值调大（降低优先级），调小需要 root 权限。
检查点：能启动 sleep 300 &、保存并打印 PID、用 ps -p 确认存在，kill 后再次用 ps -p 确认进程已经结束。

1.5 free 查看内存

free 查看物理内存和交换空间（Swap）。加 -h 用更适合人阅读的单位显示。

Step 1 / 查看内存概况
free
free -h

预期输出（数值随机器变化）：

              total        used        free      shared  buff/cache   available
Mem:           1.8G        620M        180M         9M        1.0G        1.0G
Swap:          2.0G          0B        2.0G
Step 2 / 观察自动刷新（可选）
free -h -s 2
# 每 2 秒刷新一次，按 Ctrl+C 结束
  • Mem 行与 Swap 行分别表示什么？
  • free 列的数值很小，就说明内存一定不够用吗？应该重点看哪一列？
  • free、buff/cache 与 available 三者有什么关系？
Linux 会把空闲内存用于缓存，所以 free 很小是常见现象。buff/cache 在需要时可以回收，判断“还能不能用”应重点看 available。
检查点：能读出内存总量、已用量和可用量，并能说出 Mem 与 Swap 的区别。

1.6 df、du 查看磁盘

df -h 从文件系统层面看各挂载点的总容量与剩余空间；du -sh 从目录层面统计某个目录及其内容占用了多少空间。两者统计对象不同，数值不必完全相等。

Step 1 / 查看文件系统空间
df -h

预期输出（分区与容量以实际为准）：

Filesystem               Size  Used Avail Use% Mounted on
/dev/mapper/centos-root   50G  8.1G   42G  16% /
devtmpfs                 1.9G     0  1.9G   0% /dev
tmpfs                    1.9G     0  1.9G   0% /dev/shm
tmpfs                    1.9G  9.0M  1.9G   1% /run
/dev/sda1               1014M  153M  862M  15% /boot
Step 2 / 统计目录占用
du -sh ~
du -sh ~/LinuxProject
du -sh ~/ArchiveLab
du -sh ~/LinuxProject/* | sort -h | tail -n 5

预期输出（数值示意）：

1.2G    /home/njucm
1.3M    /home/njucm/LinuxProject
160K    /home/njucm/ArchiveLab
228K    /home/njucm/LinuxProject/logs
1.0M    /home/njucm/LinuxProject/archive
Step 3 / 进程与资源命令对照
命令主要看什么关键字段 / 选项典型用途
uname -a内核与主机信息内核版本、架构确认系统环境
uptime运行时长与负载load average 的 1、5、15 分钟值判断系统忙不忙
date系统时间与时区年、月、日、时分秒、CST记录操作时间
ps aux进程快照与资源占用USER、PID、%CPU、%MEM、STAT、COMMAND找占用较高的进程
ps -ef完整进程列表UID、PID、PPID、C、CMD查父子进程关系
top动态进程与资源%Cpu(s)、KiB Mem、P / M / q实时观察变化
pgrep按名称查找 PID-a 显示命令、-x 精确匹配、-f 匹配完整命令行定位测试进程
kill向进程发送信号-15 正常结束、-9 强制结束结束自己的测试进程
free -h内存与 Swaptotal、used、free、available看内存够不够
df -h文件系统空间Size、Used、Avail、Use%、Mounted on看分区是否快满
du -sh目录或文件占用-s 只显示汇总、-h 易读单位找出占空间最大的目录
nice / renice进程优先级-n 指定 nice 值拓展了解，本课不作必做要求
  • df -h 的 Use% 与 du -sh 的结果为什么不能直接相等？
  • 如果根分区快满了，应该先用 df -h 还是 du -sh？接下来再怎么定位？
  • du -sh ~/LinuxProject/* 与 du -sh ~/LinuxProject 有什么区别？
排查“磁盘满”的顺序通常是：先用 df -h 找到快满的挂载点，再进入该挂载点用 du -sh * | sort -h 逐层定位大目录。不要在不确认对象的情况下直接删除文件。
检查点：能读出根分区的总容量、已用量与剩余量；能用 du -sh 比较 ~/LinuxProject 与 ~/ArchiveLab 的大小。
