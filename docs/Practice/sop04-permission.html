实验4：用户、用户组与权限

Linux 的权限系统只回答三个问题：我是谁、文件属于谁、权限给了谁。本页先确认身份，再逐位读懂 ls -l，最后用符号法和数字法修改权限，并在 ~/PermLab 中验证一次 Permission denied 的定位与修复。

本课目标 能用 whoami、id、groups 确认身份；能逐位解读 ls -l 的权限串；能区分文件和目录上的 rwx；能用 chmod 的符号法与数字法设置 644、600、755、700；理解 chown、chgrp 与 sudo 的边界
项目阶段 项目权限检查与最小授权。用 ~/PermLab 验证文件、目录与脚本的权限，不随意改动 LinuxProject 的原始数据
练习方式 在 CentOS 课程虚拟机中亲手输入命令，截图留存结果，再按实验报告模板提交到雨课堂

1. 练习

1.1 确认身份：whoami、id、groups

遇到 Permission denied 时，第一步不是改权限，而是先确认“当前是谁”。三条命令分别回答用户名、UID/GID 与所属组。

Step 1 / 逐条执行
whoami
id
groups
pwd
Step 2 / 参考输出（组列表与主机名以实际环境为准）
njucm
uid=1000(njucm) gid=1000(njucm) groups=1000(njucm)
njucm : njucm
/home/njucm
  • whoami：当前登录用户名，课程环境应为 njucm
  • id：uid 是用户编号，gid 是主组编号，groups 是全部所属组
  • groups：只列出当前用户所在的组，格式为“用户名 : 组名”
  • pwd：当前目录，登录后通常为 /home/njucm
不同虚拟机的 UID、GID 和附加组可能不同，不要背死数字。先看 id 输出中的名字，再用 ls -l 对照文件所有者和所属组。
检查点：能指出 id 输出中哪一段是 UID、哪一段是 GID，并说出当前用户属于哪些组。

1.2 读懂 ls -l 的权限串

ls -l 的第一列是十位权限串，不是乱码。先把它分成“1 位类型 + 3 组 3 位权限”，再按 owner、group、others 分别读。

Step 1 / 创建自己的权限练习目录
cd ~
mkdir -p PermLab
cd PermLab
touch public.txt secret.txt run.sh
mkdir data
touch data/note.txt
ls -l
ls -ld data
Step 2 / 参考输出（时间与大小随环境略有不同）
-rw-r--r-- 1 njucm njucm 0 ... public.txt
-rw-r--r-- 1 njucm njucm 0 ... secret.txt
-rw-r--r-- 1 njucm njucm 0 ... run.sh
drwxr-xr-x 2 njucm njucm 6 ... data

新建文件和目录的初始权限由系统的 umask 决定，常见结果是文件 644、目录 755，也可能与这里略有不同。以你自己的 ls -l 输出为准，后面的 chmod 数字法会统一设置目标权限。

位置示例含义
第 1 位- / d对象类型：- 普通文件，d 目录，l 符号链接
第 2–4 位rw-owner（文件所有者）的权限
第 5–7 位r--group（所属组）的权限
第 8–10 位r--others（其他用户）的权限
查看目录本身要用 ls -ld data；ls -l data 列出的是 data 里面的内容，不是 data 目录自己的权限。两条命令差一个 -d，结果完全不同。
检查点：能指出 public.txt 的 owner、group、others 各有哪些权限，并解释为什么 data 行首是 d。

1.3 rwx 对文件和目录的不同含义

同样是 r、w、x，作用在文件上和目录上含义不同。目录最容易混淆的是 x：它表示“可以进入/穿越”，不只是“可以执行”。

权限对文件对目录
r read可以读取文件内容可以列出目录中的名称
w write可以修改文件内容可以在目录中创建、删除或重命名条目，通常还需要 x
x execute / enter允许作为程序执行允许进入目录，并访问其中已知名称的对象
  • drwxr-xr-x：目录；所有者可读、写、进入；组和其他用户可读、可进入，但不能写
  • -rw-r--r--：普通文件；所有者可读写；组和其他用户只读
  • 文件有 r 但没有 x 时，可以 cat，但不能 ./文件名 执行
  • 目录有 r 但没有 x 时，能看到名称，却无法真正进入和访问内部对象
判断目录权限时要同时看 r 和 x。只有 r 没有 x，ls 可能列出名字，但 cd 会失败；只有 x 没有 r，能进入但看不到目录列表。
检查点：能用自己的话解释“目录的 x 是进入/穿越”，并举出文件 x 与目录 x 各一个不同场景。

1.4 chmod 符号法

符号法的写法是“给谁 + 做什么 + 什么权限”：u 所有者、g 所属组、o 其他用户、a 全部；+ 增加、- 删除、= 直接设置。它只改动指定的位，适合局部微调。

Step 1 / 先看修改前
ls -l public.txt secret.txt run.sh
Step 2 / 一次只改一位，改完立即验证
chmod u+x run.sh
ls -l run.sh
chmod o-r secret.txt
ls -l secret.txt
chmod g+w public.txt
ls -l public.txt
chmod g-w public.txt
ls -l public.txt
Step 3 / 预期变化
run.sh     -rw-r--r-- -> -rwxr--r--
secret.txt -rw-r--r-- -> -rw-r-----
public.txt -rw-r--r-- -> -rw-rw-r-- -> -rw-r--r--
  • u+x run.sh：只给所有者增加执行权限，组和其他用户的位不变
  • o-r secret.txt：只删除其他用户的读权限
  • g+w 后再 g-w：观察所属组写权限增加又删除
  • 每次 chmod 后都用 ls -l 验证，不要连续改完才检查
先在纸上写出“改完应该是什么权限串”，再执行命令对照。符号法只碰你指定的那一位；如果初始权限中本来就没有 w，g-w 不会产生任何变化，这不是命令失效。
检查点：能预测 u+x、o-r、g+w 执行后的三位权限，并用 ls -l 证明预测正确。

1.5 chmod 数字法

数字法把 r、w、x 分别记作 4、2、1，再把每组三位相加。一个三位数就同时设置 owner、group、others 的全部权限，所以一次会覆盖九位。

Step 1 / 设置四个常见权限
chmod 644 public.txt
chmod 600 secret.txt
chmod 755 run.sh
chmod 700 data
ls -l public.txt secret.txt run.sh
ls -ld data
Step 2 / 参考输出
-rw-r--r-- ... public.txt
-rw------- ... secret.txt
-rwxr-xr-x ... run.sh
drwx------ ... data
数字权限串含义
7rwx读 + 写 + 执行/进入
6rw-读 + 写
5r-x读 + 执行/进入
4r--只读
2-w-只写
1--x只执行/进入
0---无权限
数字权限权限串常见含义典型对象
644-rw-r--r--自己可读写，组和其他用户只读普通文档、配置文件
600-rw-------只有自己可读写私密文件
755-rwxr-xr-x自己可读写执行，组和其他用户可读执行可执行脚本、公共目录
700drwx------只有自己拥有全部权限私有目录
  • 644：owner 6 = rw，group 4 = r，others 4 = r
  • 600：owner 6 = rw，group 0、others 0 都没有权限
  • 755：owner 7 = rwx，group 5 = r-x，others 5 = r-x
  • 700：owner 7 = rwx，其他两组都是 0
数字法会把九位权限整体重写，执行前先想清楚“组和其他用户是否应该保留权限”。千万不要把 chmod 777 当成“修复权限”的默认做法；它让所有用户都能读、写、执行，远超完成任务所需的权限。
检查点：能从 644、600、755、700 推出对应的 rwx，也能从“自己读写、组只读、其他无权限”的需求反推出 640。

1.6 chown、chgrp 与 sudo 边界

chown 修改文件所有者，chgrp 只修改文件所属组。普通用户通常只能把文件交给“自己”，不能把所有权转给别人；这正是权限系统在保护你的数据。

Step 1 / 观察可以执行与不能执行的 chown
ls -l public.txt
chown njucm public.txt
chgrp njucm public.txt
ls -l public.txt
chown root public.txt
ls -l public.txt
Step 2 / 预期结果
chown: changing ownership of 'public.txt': Operation not permitted
-rw-r--r-- 1 njucm njucm 0 ... public.txt
  • chown njucm public.txt：所有者本来就是自己，命令成功但没有变化
  • chgrp njucm public.txt：改成自己所属的主组，允许执行
  • chown root public.txt：普通用户不能把文件“送”给 root，报 Operation not permitted
  • chown 用户:组 文件 可同时改所有者和组；-R 表示递归处理目录内容，使用前要确认范围
Step 3 / 认识 sudo 的边界（只检查，不依赖）
sudo -n -l
# 若提示 may not run sudo 或 a password is required，
# 说明当前课程账号没有免密 sudo 权限，这是正常现象
  • sudo 让被授权的用户临时以管理员身份执行指定命令，是否允许由 /etc/sudoers 决定
  • 它不能把“不会权限”变成“会权限”；执行前仍要看报错、身份与文件权限
  • 本课程能用当前用户在自己的主目录解决的问题，不要先加 sudo
最小权限原则：能只加 u+x，就不要改成 777；能只改组权限，就不要把所有者交给别人。sudo 是受控的管理入口，不是绕过权限理解的捷径。
检查点：能说出 chown 与 chgrp 的区别，解释为什么 chown root 会失败，并说明 sudo 能做什么、不能做什么。

1.7 制造并解决 Permission denied

权限报错最适合用“制造一次、定位一次、修复一次”的方式理解。先让脚本缺少执行权限，再只补上所需的那一位。

Step 1 / 写入一个只输出一行文字的脚本
printf '#!/bin/bash\necho "Hello Permission"\n' > run.sh
chmod 644 run.sh
./run.sh
ls -l run.sh
Step 2 / 预期报错与权限串
bash: ./run.sh: Permission denied
-rw-r--r-- 1 njucm njucm 0 ... run.sh

文件有读权限、没有执行权限，所以 shell 拒绝执行。不要直接 sudo，先补上 owner 的 x：

chmod u+x run.sh
ls -l run.sh
./run.sh
Step 3 / 再验证目录的 x 权限
mkdir -p testdir
touch testdir/a.txt
chmod 600 testdir
ls -ld testdir
cd testdir
chmod 700 testdir
cd testdir
pwd
Step 4 / 预期结果
drw------- ... testdir
bash: cd: testdir: Permission denied
/home/njucm/PermLab/testdir
  • chmod 600 testdir 后：所有者有读写但没有 x，因此无法进入目录
  • chmod 700 testdir 后：所有者恢复 rwx，可以进入并用 pwd 确认位置
  • 目录里的文件权限设置得再宽松，只要目录本身缺少 x，外部访问仍会被挡住
排错顺序：读报错 → pwd / ls 确认对象 → id / ls -l 确认身份与权限 → 做最小修改 → 再次验证。遇到 Permission denied 先判断缺少哪一位，不要条件反射地 sudo 或 chmod 777。
检查点：能完整复现一次脚本的 Permission denied 和一次目录的 Permission denied，分别指出缺少的权限位，并用最小修改修复后再次运行成功。

2.2 任务 B：最小权限与解释（拓展）

  • 对同一个权限为 644 的文件，分别执行 chmod u+x 与 chmod 755，写出两种结果并说明组和其他用户的权限差异
  • 把 data/note.txt 设为 600，解释在 data 为 700 的情况下，组和其他用户为什么仍然无法读取它
  • 执行一次 chown root secret.txt，记录报错原文，并说明为什么普通用户不能把所有权转给别人
  • 任选一个文件，写出“当前权限、实际需求、最小修改命令、修改后权限”四栏对照
  • 用 2–3 句话说明为什么 chmod 777 不是修复权限问题的合理做法
最小权限不是“越少越好到不能干活”，而是“刚好够完成任务”。公共脚本需要其他人读和执行，就给 755；私密文件只给自己读写，就给 600；私有目录只给自己进入，就给 700。
