实验5：文本搜索与统计

日志文件有一百多行时，逐行翻看既慢又容易漏。本页从 app.log 出发，练习用 grep 找出符合条件的整行，再用 wc -l 与管道统计数量。学完后，你应该能独立回答两个问题：哪些行符合条件？一共有多少行？

本课目标 掌握 grep 基本搜索与 -i、-n、-v、-w 及组合选项；掌握 wc -l；理解管道 | 如何把上一条命令的输出交给下一条命令
项目阶段 日志分析。对模拟日志 app.log 完成搜索、定位与数量统计，为后续文本处理实验打基础
练习方式 在 CentOS 课程虚拟机中亲手输入命令，截图留存结果，再按实验报告模板提交到雨课堂

1. 练习

1.1 先认识 app.log

本次实验只用一个文件：app.log。它是 120 行的模拟 Linux 应用日志，每行由时间戳、日志级别、进程与请求信息、日志内容组成。先把文件放进 ~/Desktop/LogLab，再核对行数。

Step 1 / 准备 LogLab 并核对文件
cd ~/Desktop
mkdir -p LogLab
mv app.log LogLab/          # 若 app.log 已经拖进 LogLab，这一条可跳过
cd LogLab
pwd
wc -l app.log
head -3 app.log

预期输出：

/home/njucm/Desktop/LogLab
120 app.log
2026-11-06 08:00:00 [INFO] pid=2100 thread=worker-1 request_id=req-0001 Application startup completed; service is accepting requests
2026-11-06 08:04:00 [WARN] pid=2101 thread=worker-2 request_id=req-0002 Response time exceeded the expected threshold
2026-11-06 08:08:00 [ERROR] pid=2102 thread=worker-3 request_id=req-0003 Database connection failed after three attempts
  • 文件一共有多少行？wc -l 显示的数字与文件名分别表示什么？
  • 前 3 行的日志级别分别是什么？
  • 日志级别外面为什么有方括号 [INFO]？搜索时关键词要不要带方括号？
本页所有命令都只读取 app.log，不会修改原始文件。搜索关键词时不带方括号，例如写 grep "ERROR" app.log，不要写成 grep "[ERROR]" app.log。
检查点：pwd 显示 /home/njucm/Desktop/LogLab，wc -l app.log 显示 120 行，能说出每行日志的基本结构。

1.2 grep 基本搜索

grep 在文件中搜索符合条件的行，默认区分大小写，输出的是包含关键词的整行，而不只是关键词本身。

Step 1 / 搜索大写 ERROR 与 INFO
cd ~/Desktop/LogLab
grep "ERROR" app.log
grep "INFO" app.log | wc -l
grep "error" app.log | wc -l

预期输出（grep "ERROR" 实际共 10 行，这里列出前 3 行）：

2026-11-06 08:08:00 [ERROR] pid=2102 thread=worker-3 request_id=req-0003 Database connection failed after three attempts
2026-11-06 08:44:00 [ERROR] pid=2114 thread=worker-3 request_id=req-0015 Unable to write report file to the output directory
2026-11-06 09:20:00 [ERROR] pid=2109 thread=worker-3 request_id=req-0027 Authentication service returned an invalid response
40
10

默认搜索下，ERROR、Error、error 是三种不同的写法，各出现 10 次；大写 INFO 共 40 行。

写法作用在 app.log 上的结果
grep "ERROR" app.log区分大小写，只匹配大写 ERROR10 行
grep -i "error" app.log忽略大小写，三种写法都算30 行
grep -n "ERROR" app.log显示匹配行在原文件中的行号10 行，每行前带行号
grep -v "INFO" app.log反向筛选，保留不含 INFO 的行80 行
grep -w "error" app.log整词匹配，避免匹配到更长的单词10 行
wc -l app.log统计文件总行数120 行
grep ... app.log | wc -l统计匹配结果的行数随关键词和选项变化
grep 只是把符合条件的行显示到终端，不会删除、修改或重排原文件。命令中关键词与文件名之间用空格分开，关键词建议用引号括起来。
检查点：能指出命令中哪部分是关键词、哪部分是文件名；能解释输出为什么是整行而不是只有 ERROR。

1.3 grep -i 忽略大小写

-i 让搜索忽略大小写。日志中同时存在 ERROR、Error、error 三种写法，只有加上 -i 才能一次找全。

Step 1 / 比较加与不加 -i
grep "error" app.log | wc -l
grep -i "error" app.log | wc -l
grep -i "error" app.log | head -5

预期输出：

10
30
2026-11-06 08:08:00 [ERROR] pid=2102 thread=worker-3 request_id=req-0003 Database connection failed after three attempts
2026-11-06 08:12:00 [Error] pid=2104 thread=worker-1 request_id=req-0005 Payment callback could not be verified
2026-11-06 08:24:00 [error] pid=2108 thread=worker-1 request_id=req-0009 token refresh failed for the current session
2026-11-06 08:44:00 [ERROR] pid=2114 thread=worker-3 request_id=req-0015 Unable to write report file to the output directory
2026-11-06 08:48:00 [Error] pid=2116 thread=worker-1 request_id=req-0017 Session data was rejected because its signature was invalid
  • 不加 -i 只有 10 行，加上 -i 为什么变成 30 行？
  • 30 行正好是 10 + 10 + 10，分别对应哪三种写法？
  • 把关键词换成 info，grep -i "info" app.log | wc -l 会得到多少行？
-i 只改变“比较时是否区分大小写”，不会把文件中的大写改成小写，也不会修改文件内容。输出仍然保持原来的大小写。
检查点：能解释 10 与 30 的差别，并能说出 -i 只影响匹配规则、不影响文件内容。

1.4 grep -n 显示行号与组合选项

-n 在每条匹配结果前加上它在原文件中的行号。行号是定位日志的坐标，看到 3: 就知道问题在原文件第 3 行。

Step 1 / 单独使用 -n 与组合 -in
grep -n "ERROR" app.log | head -3
grep -in "error" app.log | head -5
grep -c "ERROR" app.log

预期输出：

3:2026-11-06 08:08:00 [ERROR] pid=2102 thread=worker-3 request_id=req-0003 Database connection failed after three attempts
15:2026-11-06 08:44:00 [ERROR] pid=2114 thread=worker-3 request_id=req-0015 Unable to write report file to the output directory
27:2026-11-06 09:20:00 [ERROR] pid=2109 thread=worker-3 request_id=req-0027 Authentication service returned an invalid response
3:2026-11-06 08:08:00 [ERROR] pid=2102 thread=worker-3 request_id=req-0003 Database connection failed after three attempts
5:2026-11-06 08:12:00 [Error] pid=2104 thread=worker-1 request_id=req-0005 Payment callback could not be verified
9:2026-11-06 08:24:00 [error] pid=2108 thread=worker-1 request_id=req-0009 token refresh failed for the current session
15:2026-11-06 08:44:00 [ERROR] pid=2114 thread=worker-3 request_id=req-0015 Unable to write report file to the output directory
17:2026-11-06 08:48:00 [Error] pid=2116 thread=worker-1 request_id=req-0017 Session data was rejected because its signature was invalid
10
  • 3: 中的 3 表示什么？是第 3 条匹配，还是原文件第 3 行？
  • grep -in 与 grep -i -n 是否等价？
  • grep -c "ERROR" app.log 输出 10，与 grep "ERROR" app.log | wc -l 有什么区别？
多个短选项可以合并写在同一个横杠后面，例如 -in 就是 -i 加 -n。行号只是显示信息，不会写回文件。
检查点：能解释 3: 是原文件行号；能写出“忽略大小写并显示行号”的命令 grep -in "error" app.log。

1.5 grep -v 反向筛选与 -w 整词匹配

-v 表示反向选择：保留不匹配关键词的行。-w 表示整词匹配：只有当关键词作为一个完整单词出现时才匹配，避免把 connect 误匹配到 connection。

Step 1 / 排除记录并观察整词匹配
grep -v "INFO" app.log | wc -l
grep -iv "error" app.log | wc -l
grep -w "error" app.log | wc -l
grep "connect" app.log | wc -l
grep -w "connect" app.log | wc -l

预期输出：

80
90
10
8
0
  • 文件共 120 行，grep -v "INFO" 为什么得到 80 行？
  • grep -iv "error" 先忽略大小写再排除，为什么得到 90 行？
  • connect 能匹配到 8 行，但整词匹配 -w "connect" 却是 0 行，为什么？
-v 不是“删除行”，只是让这些行不进入输出。配合 -i 使用时要小心：grep -iv "error" 会排除所有大小写形式的 error 行，剩下的才是输出。
检查点：能说出 -v 保留的是“不含关键词的行”；能举出 connection 包含 connect 但不属于整词匹配的例子。

1.6 wc -l 与管道统计

wc -l 统计输入中有多少个换行符，也就是多少行。| 把左边命令的输出直接交给右边命令，所以可以用 grep | wc -l 统计匹配行数。

Step 1 / 文件总行数与匹配行数
wc -l app.log
cat app.log | wc -l
grep "ERROR" app.log | wc -l
grep -i "error" app.log | wc -l
grep "INFO" app.log | wc -l
grep -v "INFO" app.log | wc -l

预期输出：

120 app.log
120
10
30
40
80
  • wc -l app.log 带文件名，cat app.log | wc -l 为什么不带文件名？
  • 为什么 wc -l app.log 是 120，而 grep -i "error" app.log | wc -l 只有 30？
  • 管道符 | 两边分别负责什么？它有没有修改 app.log？
排错顺序：先 pwd、ls 确认文件位置 → 再检查关键词大小写 → 再检查选项是否写错（wc -l 不要写成 wc -1）→ 最后检查管道两侧的命令是否完整。若 grep 没有输出，先试 -i。
检查点：能预测并核对 120、10、30、40、80 这几个数字分别来自哪条命令；能解释“总行数”与“匹配行数”的区别。
