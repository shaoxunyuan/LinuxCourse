实验8：文本编辑与替换

修改文本时，最安全的顺序是“先看、再预览、最后才写回”。本页用 sed 完成指定行查看、批量替换、按模式删除和管道组合，再用 Vim 与 Nano 修改 hospital.conf 的日志级别，并学会在 sed -i 之前备份。

本课目标 能读懂 sed 的 -n、p、s///、g、d、-i；能在 Vim / Nano 中完成最小编辑并安全改写配置
项目阶段 文本维护与配置修改。批量处理成绩记录，修改 ~/LinuxProject/config/hospital.conf 并核对结果
练习方式 在 CentOS 课程虚拟机中亲手输入命令，截图留存结果，再按实验报告模板提交到雨课堂

1. 练习

1.1 先观察：sed -n 只看指定行

sed 默认逐行读取文件，把每一行都输出到终端。加上 -n 会关闭默认输出，再配合 p 只打印你指定的行或匹配行。

Step 1 / 建立 SedLab 并准备两个文件
cd ~/Desktop
mkdir -p SedLab
cd SedLab
cp ~/Desktop/scores.csv .
cat > notes.txt <<'EOF'
2026-08-01 old draft: first note
2026-08-02 old record: replace old once
2026-08-03 draft status: old marker appears twice old
2026-08-04 INFO course record ready
2026-08-05 WARN disk almost full
2026-08-06 ERROR cannot open config
2026-08-07 draft note: Linux practice
2026-08-08 INFO backup finished
2026-08-09 WARN network slow
2026-08-10 draft summary: old value kept
EOF
pwd
ls
wc -l scores.csv notes.txt

预期输出：

/home/njucm/Desktop/SedLab
notes.txt
scores.csv
 31 scores.csv
 10 notes.txt
 41 total
Step 2 / 只查看 scores.csv 的前 10 行
sed -n '1,10p' scores.csv

预期输出：

Name,Score,Class
Alice,88,Class1
Bob,72,Class1
Cindy,95,Class2
David,60,Class2
Eva,100,Class3
Frank,88,Class1
Grace,45,Class2
Henry,9,Class3
Ivy,18,Class1
  • '1,10p' 中的 p 是打印命令，1,10 是行号范围。
  • 去掉 -n 再执行一次，会看到这 10 行被打印两遍：一次是默认输出，一次是 p。
  • sed -n '8p' scores.csv 只显示第 8 行，可用来核对单行。
牢记：p 必须与 -n 配合。只写 p 不加 -n，同一行会重复出现，很多“输出越来越多”的困惑都来自这里。
检查点：能只显示第 1～10 行，并说出 -n 与 p 各自的作用。

1.2 s/// 首次替换与 g 全部替换

s/旧/新/ 表示替换，默认只替换每行中第一次出现的旧内容；在末尾加 g，才会替换这一行里的全部匹配。先不加 -i，只观察终端输出。

Step 1 / 先看要替换的原始行
grep '2026-08-02' notes.txt
grep -o 'old' notes.txt | wc -l

预期输出：

2026-08-02 old record: replace old once
6
Step 2 / 首次替换与全局替换
sed 's/old/new/' notes.txt | head -n 3
sed 's/old/new/g' notes.txt | head -n 3

预期输出：

2026-08-01 new draft: first note
2026-08-02 new record: replace old once
2026-08-03 draft status: new marker appears twice old
2026-08-01 new draft: first note
2026-08-02 new record: replace new once
2026-08-03 draft status: new marker appears twice new
  • 不加 g 时，第 2 行只替换了第一个 old，后面的 old 仍然保留。
  • 加 g 后，第 2 行两个 old 都变成 new；第 3 行的两个 old 也同样全部替换。
  • 两次命令都没有写回文件，原文件仍有 6 处 old，可用 grep -o 'old' notes.txt | wc -l 复核。
“先看再改”的标准动作：先用不带 -i 的 sed 预览替换结果，确认行号、大小写和匹配范围都正确，再决定是否写回文件。
检查点：能指出第 2 行替换前后差异，并解释 g 为什么让同一行的多个 old 都被换掉。

1.3 sed -i 就地修改与备份

-i 表示直接修改文件本身，终端不会再输出替换结果。它没有“撤销”按钮，写错模式就会改错文件，因此执行前必须先备份。

Step 1 / 在副本上练习 -i
cp scores.csv scores_demo.csv
cp scores_demo.csv scores_demo.csv.bak
sed -i 's/Class1/ClassOne/g' scores_demo.csv
head -n 4 scores_demo.csv
grep -c 'ClassOne' scores_demo.csv
grep -c 'Class1' scores.csv
ls scores_demo.csv*

预期输出：

Name,Score,Class
Alice,88,ClassOne
Bob,72,ClassOne
Cindy,95,Class2
11
11
scores_demo.csv
scores_demo.csv.bak
  • sed -i 执行时没有输出，这是正常的；用 head、grep 才能确认文件真的被改了。
  • 副本中 ClassOne 出现 11 次，而原始 scores.csv 中的 Class1 仍是 11 次，说明原文件没有被误改。
  • 备份文件 scores_demo.csv.bak 的作用是：改错时可以用 cp scores_demo.csv.bak scores_demo.csv 恢复。
公式：cp 文件 文件.bak → 预览 sed 输出 → 确认无误后 sed -i → diff 文件.bak 文件 核对。顺序颠倒，就可能把唯一一份数据改坏。
检查点：能说出 sed -i 与不带 -i 的 sed 的区别，并展示备份文件确实存在。

1.4 按行号或模式删除 d

d 表示删除当前行。它同样只影响“输出结果”，不加 -i 时不会改动原文件。既能按行号删除，也能按关键词模式删除。

Step 1 / 按行号删除与按模式排除
sed '3d' notes.txt | head -n 4
sed -n '/ERROR/p' notes.txt
sed '/ERROR/d' notes.txt
wc -l notes.txt

预期输出：

2026-08-01 old draft: first note
2026-08-02 old record: replace old once
2026-08-04 INFO course record ready
2026-08-05 WARN disk almost full
2026-08-06 ERROR cannot open config
2026-08-01 old draft: first note
2026-08-02 old record: replace old once
2026-08-03 draft status: old marker appears twice old
2026-08-04 INFO course record ready
2026-08-05 WARN disk almost full
2026-08-07 draft note: Linux practice
2026-08-08 INFO backup finished
2026-08-09 WARN network slow
2026-08-10 draft summary: old value kept
10 notes.txt
  • sed '3d' 删掉第 3 行，所以输出从第 4 行继续。
  • sed -n '/ERROR/p' 只打印包含 ERROR 的 1 行；sed '/ERROR/d' 输出其余 9 行。
  • 最后 wc -l 仍是 10，证明前面的删除只影响了屏幕输出，原文件没有被改写。
d 与 p 是一对相反操作：p 留下匹配行，d 排除匹配行。是否写回文件，仍然由有没有 -i 决定。
检查点：能分别用行号 3d 和模式 /ERROR/d 删除，并说明原文件为什么仍保留 10 行。

1.5 sed 与管道组合

管道 | 把前一条命令的输出交给后一条命令作为输入。可以先取行，再替换；也可以先筛选，再格式化。

Step 1 / 先取第 2～6 行，再替换班级名
sed -n '2,6p' scores.csv | sed 's/Class1/ClassOne/g'

预期输出：

Alice,88,ClassOne
Bob,72,ClassOne
Cindy,95,Class2
David,60,Class2
Eva,100,Class3
sed 写法作用本次数据的实际效果
sed 's/old/new/'每行只替换第一次匹配第 2 行只换第一个 old
sed 's/old/new/g'每行替换全部匹配6 处 old 全部变成 new
sed -n '1,10p'只打印第 1～10 行scores.csv 前 10 行
sed -n '/ERROR/p'只打印匹配行notes.txt 中 1 行 ERROR 记录
sed '/ERROR/d'排除匹配行后输出其余行10 行输出变成 9 行
sed -i 's/旧/新/g'直接写回原文件无屏幕输出，需提前备份并复核
命令 | sed '...'把前一条命令的输出交给 sed先筛选行，再对剩余文本替换
Step 2 / 筛选与格式化再组合
awk -F ',' 'NR>1 && $2 >= 90 {print $1, $2}' scores.csv | sed 's/ /,/g' | head -n 4

预期输出：

Cindy,95
Eva,100
Lily,91
Peter,100
管道组合不会自动保存结果。屏幕上看到的是处理后的输出；若想保存，需要另写重定向，例如 ... > result.txt，并先确认不会覆盖重要文件。
检查点：能解释管道中后一个 sed 的输入来自哪里，并说明原文件在管道组合后是否被修改。

1.6 Vim、Nano 与配置文件修改

Vim 有三种常用模式：一般模式（打开后默认所在，用来移动、复制、删除）、插入模式（按 i 进入，真正输入文字）、命令行模式（按 : 进入，执行保存与退出）。按 Esc 可以从插入模式回到一般模式。

Step 1 / Vim 最小操作
cd ~/Desktop/SedLab
vim notes.txt

# 在 Vim 中依次按键
i                         # 进入插入模式
2026-08-11 INFO vim edit  # 新起一行输入内容
Esc                       # 回到一般模式
:w                        # 保存
:q                        # 退出
# 如果改错了不想保存：按 Esc，再输入 :q! 强制退出
# 想保存并退出：按 Esc，再输入 :wq
Step 2 / Nano 保存与退出
nano notes.txt

# 在 Nano 中依次按键
Ctrl+O    # 写入保存，按 Enter 确认文件名
Ctrl+X    # 退出编辑器
  • Vim 中 :wq 等于“保存并退出”，:q! 等于“不保存强制退出”。
  • Nano 底部会显示快捷键提示，^O 表示 Ctrl+O，^X 表示 Ctrl+X。
  • 编辑后回到终端，用 wc -l notes.txt 和 tail -n 2 notes.txt 核对内容是否真的写入。
Step 3 / 修改 hospital.conf 的日志级别
cd ~/LinuxProject/config
sed -n '1,4p' hospital.conf
cp hospital.conf hospital.conf.bak
sed -i 's/log_level=INFO/log_level=DEBUG/' hospital.conf
grep 'log_level' hospital.conf
diff hospital.conf.bak hospital.conf
ls hospital.conf*

预期输出：

# Hospital application configuration
app_name=HospitalDemo
mode=production
log_level=INFO
log_level=DEBUG
4c4
< log_level=INFO
---
> log_level=DEBUG
hospital.conf
hospital.conf.bak
  • sed -n '1,4p' 先确认原配置里确实写着 log_level=INFO。
  • 备份文件名建议固定为 hospital.conf.bak，恢复命令是 cp hospital.conf.bak hospital.conf。
  • diff 输出的 4c4 表示第 4 行被修改，< 是备份中的旧值，> 是修改后的新值。
  • 只改配置文本并不等于服务立刻生效；本实验只要求正确改写并核对文件内容。
修改系统或项目配置前，一律先备份。若 sed -i 执行后发现改错，立即用备份恢复，不要在原文件上反复尝试替换。
检查点：能说出 Vim 三种模式及 :wq 与 :q! 的区别，并能用 grep 证明 log_level=DEBUG 已写入。
