实验11：正则表达式

实验5里我们只会搜索固定的字符串：ERROR 就是 ERROR，error 就是 error。实验8用 sed 做替换时，也只能按固定文字改。本页把“固定字符串”升级成“模式匹配”：用一套描述规则的方法，一次抓住一整类符合形状的内容，例如任意 4 位请求编号、任意大小的成绩、行首的时间戳。学完后，你应当能读懂并写出常见正则，还能用它配合 grep、sed、awk 完成日志分析和格式校验。

本课目标 理解正则“描述模式而不是固定文字”；掌握锚点、字符集合、量词、字符类、分组与“或”；能在 grep -E、sed、awk 中写正则并验证结果

1. 练习

1.1 为什么需要正则：固定字符串 vs 模式

固定字符串只能表述“这几个字必须原样出现”。正则表达式（regular expression，常写作 regex）表述的是“形状”：第几个位置是什么类型、重复几次、哪些字符可选。两者是同一件事的两种描述能力。

Step 1 / 准备实验目录
cd ~/Desktop
mkdir -p RegExLab
mv app.log scores.csv RegExLab/     # 若文件已在目录中，可跳过
cd RegExLab
wc -l app.log scores.csv

预期输出：

120 app.log
31 scores.csv

app.log 共 120 行；scores.csv 共 31 行，其中第 1 行是表头，后面 30 行是学生成绩。

Step 2 / 同一个需求，三种写法
grep "error" app.log | wc -l          # 只要小写 error
grep -cE "[Ee]rror" app.log           # 大写 E 或小写 e 开头
grep -cE "(ERROR|Error|error)" app.log  # 三种写法都算

预期输出：

10
20
30
写法它描述什么在 app.log 上的真实结果
grep "error"固定字符串：只有连续的小写 error10 行
grep -E "[Ee]rror"模式：首字母是 E 或 e，后面固定 rror20 行（Error 10 + error 10）
grep -E "(ERROR|Error|error)"模式：三个完整备选写法之一30 行（三种各 10）

再看一个锚点的价值：固定字符串 "08:" 会连 09:08:00 这种分钟位置也一起抓进来，而锚定行首的正则只抓 8 点这一小时。

grep -c "08:" app.log
grep -cE "^2026-11-06 08:" app.log

预期输出：

24
19
正则不是“更长的关键词”，而是“形状说明书”。先想清楚要匹配的形状，再选元字符；不要一上来就堆符号。
检查点：能解释 10、20、30 三个数字分别是哪条命令的结果，并说出“固定字符串”和“模式”的区别。

1.2 位置与单个字符：^ $ . [] [^]

这一组元字符解决“在哪个位置、匹配哪一类单个字符”。默认情况下，grep 只要行内任意位置出现符合模式的一段就选中整行；锚点把匹配位置钉在行首或行尾。

Step 1 / ^ 锚定行首
grep -cE "^2026-11-06" app.log
grep -cE "^2026-11-07" app.log

预期输出：

120
0

^2026-11-06 匹配“以 2026-11-06 开头的行”，120 行全部符合；把日期改成 11-07 就没有任何行符合。对照例子：^2026-11-06 能匹配 2026-11-06 08:00:00 ...，不能匹配 INFO 2026-11-06 ...（日期不在行首）。

Step 2 / $ 锚定行尾
grep -cE "requests$" app.log
grep -cE "request$" app.log

预期输出：

1
0

requests$ 匹配“以 requests 结尾的行”，只有第 1 行的 ... service is accepting requests 符合。少写一个 s 就变成 request$，结果为 0。对照例子：requests$ 能匹配 ... accepting requests，不能匹配 ... accepting requests now。

Step 3 / . 匹配任意一个字符
grep -oE "worker-." app.log | head -3

预期输出：

worker-1
worker-2
worker-3

. 表示“任意一个字符”，注意是“一个”，不是“一串”。对照例子：c.t 能匹配 cat，不能匹配 coat（中间变成了两个字符）。想表示“任意多个字符”要写 .*。

echo "cat"  | grep -oE "c.t"
echo "coat" | grep -E "c.t"

第一条输出 cat；第二条没有任何输出（退出码为 1）。

Step 4 / [] 与 [^]
grep -cE "[Ee]rror" app.log
grep -cE "[[]ERROR[]]" app.log
grep -cE "^[^0-9]" app.log

预期输出：

20
10
0

[Ee] 匹配集合中的任意一个字符（E 或 e）；[[]ERROR[]] 用 [ ] 把方括号变成普通字符，因此匹配的是字面量 [ERROR]。[^0-9] 开头的 ^ 表示“取反”，匹配非数字字符；因为每一行都以数字年份开头，所以结果是 0。

对照例子：[^0-9]+ 能匹配整行 abc；不能匹配 a12（里面含数字）。

echo "abc" | grep -cE "^[^0-9]+$"
echo "a12" | grep -cE "^[^0-9]+$"

预期输出：

1
0
元字符匹配什么能匹配的小例子不能匹配的小例子
^行首位置^2026 → 2026-11-06 ...^2026 → INFO 2026 ...
$行尾位置requests$ → ... accepting requestsrequests$ → ... requests now
.任意一个字符（不含换行）c.t → catc.t → coat
[ ]集合中的一个字符[Ee]rror → Error[Ee]rror → ERROR
[^ ]不在集合中的一个字符[^0-9] → a[^0-9] → 7
\取消后面字符的特殊含义\. → 字面点号 .\. → 字母 a
|“或”，二选一cat|dog → dogcat|dog → cow
方括号里的 ^ 是“取反”，方括号外的 ^ 是“行首”，两个含义完全不同。写 [^0-9] 时不要把 ^ 写到括号外面。
检查点：能写出“以日期开头”和“以 requests 结尾”的两条命令；能解释 [[]ERROR[]] 为什么匹配字面方括号。

1.3 量词：* + ? {n,m}

量词说明“前一个单元重复几次”。正则里的量词只作用于它前面紧挨着的那一个字符、字符类或分组。

Step 1 / * 与 +
echo "bbb"  | grep -cE "a*b"
echo "aaab" | grep -cE "a*b"
echo "b"    | grep -cE "a+b"
echo "aab"  | grep -cE "a+b"

预期输出：

1
1
0
1

a* 表示“a 出现 0 次或多次”，所以 bbb 也能匹配；a+ 表示“a 至少出现 1 次”，所以单独的 b 不匹配。对照例子：a* 能匹配 bbb，不能匹配 ac（因为结尾要求是 b）。

Step 2 / ? 表示可有可无
echo "color colour" | grep -oE "colou?r"
echo "colr" | grep -E "colou?r"

预期输出：

color
colour

第二条命令没有输出（退出码 1）。u? 表示“u 出现 0 次或 1 次”，所以 color 与 colour 都能匹配，而 colr 中间少了 o，不匹配。

Step 3 / {n} 与 {n,m} 精确控制次数
grep -oE "[[:digit:]]{4}" app.log | head -3
grep -cE "req-01[0-9]{2}" app.log
grep -cE "req-0{2}[0-9]{2}" app.log

预期输出：

2026
2100
0001
21
99

[[:digit:]]{4} 匹配连续 4 个数字；req-01[0-9]{2} 匹配 request_id 在 0100–0199 之间的记录，共 21 行（req-0100 到 req-0120）；req-0{2}[0-9]{2} 匹配 req-0001 到 req-0099，共 99 行。

对照例子：[0-9]{3} 能匹配 100，不能匹配 88（只有两位）。在 scores.csv 中正好有 2 条三位数成绩：

grep -E ",[0-9]{3},Class[123]$" scores.csv

预期输出：

Eva,100,Class3
Peter,100,Class2
Step 4 / 量词作用于整个模式
grep -cE "request_id=req-[0-9]{4}" app.log
grep -oE "request_id=req-[0-9]{4}" app.log | head -2
grep -oE "req-[0-9]{4}" app.log | tail -2

预期输出：

120
request_id=req-0001
request_id=req-0002
req-0119
req-0120
量词含义例子能匹配不能匹配
*前一项出现 0 次或多次a*bbbbac
+前一项出现 1 次或多次a+baaabb
?前一项出现 0 次或 1 次colou?rcolorcolr
{n}恰好 n 次[0-9]{4}210088
{n,}至少 n 次[0-9]{2,}1007
{n,m}n 到 m 次req-01[0-9]{2}req-0100req-0099
* 和 + 很容易“匹配过头”。写完后先用一个具体文件或 echo 小样本测试，确认它能匹配想要的、不匹配不想要的，再拿去批量处理。
检查点：能区分 * 与 +；能解释 req-0100 被 req-01[0-9]{2} 匹配而不被 req-0{2}[0-9]{2} 匹配。

1.4 常用字符类：\d \w \s 与 POSIX 字符类

字符类是一组字符的简写。要特别注意：不同工具的“方言”不一样。CentOS 上的 GNU grep 使用扩展正则（ERE）时，支持 \w 和 \s，但不支持 \d；\d 会被当成普通字母 d。

Step 1 / 亲眼看见 \d 的真实行为
echo "dog123" | grep -oE "\d+"
echo "123"    | grep -E "\d+"; echo "exit=$?"

预期输出：

d
exit=1

第一条只输出了字母 d，说明 \d 被当作普通字符 d；第二条纯数字行反而没有匹配。想匹配数字，在 GNU grep 里请写 [0-9] 或 [[:digit:]]。

echo "abcd123" | grep -oE "[[:digit:]]+"

预期输出：

123
Step 2 / \w 与 \s
grep -oE "\w+" app.log | head -4
echo "a b" | grep -E "a\sb"

预期输出：

2026
11
06
08
a b

\w 等价于“字母、数字、下划线”，所以时间戳被切成 2026、11、06、08；\s 匹配一个空白字符。对照例子：\s 能匹配 a b 中间的空格，不能匹配 ab（没有空白）。

Step 3 / POSIX 字符类
echo "ABC123" | grep -oE "[[:upper:]]+"
echo "a,b;c"  | grep -oE "[[:punct:]]"
grep -oE "[[:digit:]]{4}" app.log | head -3

预期输出：

ABC
,
;
2026
2100
0001

POSIX 字符类写在双方括号里，例如 [[:digit:]]、[[:alpha:]]、[[:upper:]]、[[:space:]]、[[:punct:]]、[[:alnum:]]。它们比 \d 更通用，在 grep、sed、awk 中都能用。

字符类含义等价写法能匹配不能匹配
\w字母、数字、下划线[[:alnum:]_]worker_1-（连字符不属于 \w）
\s一个空白字符[[:space:]]a bab
\dGNU ERE 中不表示数字，等于字母 d改用 [[:digit:]]dog 中的 d123
[[:digit:]]0–9[0-9]2100abc
[[:alpha:]]字母[A-Za-z]Alice123
[[:upper:]]大写字母[A-Z]ABCabc
[[:space:]]空格、制表符等空白\s（GNU 扩展）a bab
[[:punct:]]标点符号无简单等价写法,2
[[:alnum:]]字母或数字[A-Za-z0-9]ab12ab-12 中的连字符本身
如果网上抄来的正则用了 \d、\b 或 (?=...) 却在 CentOS 的 grep -E 里不生效，先不要怀疑文件。多半是“方言”问题：把这些 PCRE 写法换成 POSIX 写法，或明确使用支持 PCRE 的工具。本课必做内容只用 ERE 与 POSIX 字符类。
检查点：能说出 GNU grep 中 \d 的真实含义；能把 \d+ 改写为 [[:digit:]]+ 或 [0-9]+。

1.5 分组与“或”：( ) 与 a|b

圆括号把若干字符打包成一个“单元”，竖线表示“或”。这样量词就能作用于一整组，而不是单个字符，也便于在一个模式里列出多个备选。

Step 1 / 用“或”一次覆盖多种写法
grep -cE "(ERROR|Error|error)" app.log
grep -cE " [[](INFO|WARN)[]] " app.log
grep -cE "worker-(1|2)" app.log

预期输出：

30
60
60

(ERROR|Error|error) 表示三者之一；[[](INFO|WARN)[]] 在字面方括号内选择 INFO 或 WARN，共 60 行（INFO 40 + WARN 20）；worker-(1|2) 匹配 worker-1 与 worker-2，各 30 行，合计 60。

Step 2 / 分组让量词作用于整组
echo "xyxyxy" | grep -oE "(xy){2,3}"
echo "xyxy"   | grep -cE "(xy){3}"

预期输出：

xyxyxy
0

(xy){2,3} 表示 xy 这一整组重复 2 到 3 次；写成 xy{3} 则只重复字母 y，含义完全不同。

Step 3 / 分组后的“或”用于字段值
grep -cE "^[A-Za-z]+,[0-9]{1,3},(Class1|Class2)$" scores.csv
awk -F, '$3 ~ /Class[12]/' scores.csv | wc -l

预期输出：

22
22

第一条在 CSV 行尾的班级字段用 (Class1|Class2) 二选一；第二条用 awk 的 ~ 对第三个字段做同样的正则判断，两者都得到 22 行。

Step 4 / 后向引用（只作概念提示）

把分组的内容“反引用”回来，形如 (abc)\1，可以表达“前后必须完全相同”。例如它描述 abcabc，而不描述 abcabd。这种写法叫后向引用，属于更进阶的内容：不同工具对它的支持并不一致（sed 的分组引用与 PCRE 工具中较常见），本课只要求知道这个概念，不要求用它完成任务。

# 概念示例，不必在本次实验中执行
# (abc)\1  可以描述 abcabc，不能描述 abcabd
# 需要时可用支持 PCRE 的工具，或查阅 sed 的分组引用写法
“或”的优先级很低：cat|dog 表示 cat 或 dog；如果想让“或”只作用于一小段，就用括号包起来，例如 req-(00|01)[0-9]{2}。括号也会改变量词的作用范围。
检查点：能写出匹配 INFO 或 WARN 的分组正则；能解释 (xy){2,3} 与 xy{3} 的区别。

1.6 在 grep / sed / awk 中使用正则

正则本身只是一段描述；真正干活的是调用它的工具。三个工具各有分工：grep 负责“找出符合条件的行”，sed 负责“按行编辑”，awk 负责“按字段处理”。

Step 1 / grep -E、-o、-w
grep -cE "ERROR|Error|error" app.log
grep -oE "pid=[0-9]+" app.log | head -5
grep -c "connect" app.log
grep -cE -w "connect" app.log

预期输出：

30
pid=2100
pid=2101
pid=2102
pid=2103
pid=2104
8
0

-E 启用扩展正则（直接写 |、+、{n,m}，不用反斜杠）；-o 只输出匹配到的片段而不是整行；-w 要求整词匹配，所以 connect 不会命中 connection，结果为 0。

Step 2 / sed -n '/模式/p'
sed -n "/ERROR/p" app.log | wc -l
sed -n "/^2026-11-06 08:/p" app.log | wc -l
sed -nE "/^2026-11-06 08:.*ERROR/p" app.log

预期输出：

10
19
2026-11-06 08:08:00 [ERROR] pid=2102 thread=worker-3 request_id=req-0003 Database connection failed after three attempts
2026-11-06 08:44:00 [ERROR] pid=2114 thread=worker-3 request_id=req-0015 Unable to write report file to the output directory

sed -n 默认不打印，p 表示“把匹配的行打印出来”，所以效果类似 grep。基础 sed 中竖线要写成 \|；加 -E 后可以直接写 |。

Step 3 / awk '/模式/' 与字段正则
awk '/ERROR/' app.log | wc -l
awk -F, '$3 == "Class1"' scores.csv | wc -l
awk -F, '$2 ~ /^[0-9]+$/' scores.csv | wc -l

预期输出：

10
11
30

awk '/模式/' 对整行做正则匹配；~ 表示“该字段是否匹配这个正则”；-F, 指定逗号为字段分隔符。第三个命令检查成绩字段是否全为数字，30 条数据行都符合。

涉及 sed -i（就地修改）时，务必先备份：cp scores.csv scores.csv.bak。正则写错时，sed -i 会直接改坏原文件，而备份能让你一条命令恢复。先小范围测试，再批量执行：先 grep 或 sed -n 预览，确认匹配范围后再加 -i。
检查点：能说出 -E、-o、-w 各改变什么；能写出“先预览、再备份、最后才 sed -i”的顺序。

2.2 任务 B：用正则校验 scores.csv（拓展）

用一条正则描述“合法数据行”的整体形状：姓名由字母组成、成绩 1–3 位数字、班级为 Class1/Class2/Class3、字段之间用逗号、整行从行首到行尾。再用“反向匹配”找出不符合形状的行。

Step 1 / 总行数与表头
wc -l scores.csv
head -3 scores.csv
Step 2 / 合法数据行计数
grep -cE "^[^,]+,[0-9]{1,3},Class[123]$" scores.csv
grep -vE "^[^,]+,[0-9]{1,3},Class[123]$" scores.csv
Step 3 / 排除表头后的非法行
tail -n +2 scores.csv | grep -vcE "^[^,]+,[0-9]{1,3},Class[123]$"
Step 4 / 按成绩位数分类
grep -cE ",[0-9],Class[123]$" scores.csv
grep -cE ",[0-9]{2},Class[123]$" scores.csv
