Linux 实验11｜正则表达式03

为什么需要正则：固定字符串只能“逐字相同”

同一个含义可能有多种写法，写固定字符串就要写很多条命令

grep "ERROR" app.log | wc -l
grep "Error" app.log | wc -l
grep "error" app.log | wc -l

大写

ERROR 共 10 行

首字母大写

Error 共 10 行

全小写

error 共 10 行

合计

三种写法共 30 行，要运行三次

固定字符串要求每个字符完全一致；pid=2100 也会把 pid=21000 这类更长的编号算进来。
正则表达式描述的是“一类字符串的共同结构”，一个模式就能覆盖多种写法。
Linux 实验11｜正则表达式04

正则表达式与 grep -E

模式描述“哪些字符串符合条件”，grep 负责把符合条件的行挑出来

grep -E 'ERROR|Error' app.log | wc -l

模式

用元字符写成的模板，例如 ERROR|Error

匹配

文本中有一段符合模板，这一行就被选中

输出

默认输出整行，而不是只输出匹配片段

结果

大写加首字母大写，共 20 行

本课使用的扩展正则元字符：. ^ $ [ ] [^] * + ? {n,m} ( ) |。其余字符按普通字符处理。
grep 默认使用基础正则（BRE）；grep -E 才启用扩展正则（ERE），本课统一加 -E。
Linux 实验11｜正则表达式05

元字符 .：任意一个字符

除换行符外，任意一个字符都能被 . 匹配

grep -E 'p.d=2100' app.log | wc -l
grep -E 'pid=21..' app.log | wc -l

匹配什么

恰好一个字符：字母、数字、空格、符号都可以

能匹配

p.d 可匹配 pid、pXd、p d

不能匹配

pd（少一个字符）、piid（多一个字符）

本课结果

p.d=2100 命中 8 行；pid=21.. 命中 120 行

点号本身是元字符；要匹配真正的句点，写成 \.，例如 app\.log。
Linux 实验11｜正则表达式06

锚点 ^ 与 $：限定位置

它们不匹配字符，只表示“行的开头”和“行的结尾”

grep -E '^2026-11-06' app.log | wc -l
grep -E 'requests$' app.log
grep -E '^ERROR' app.log | wc -l

^ 行首

模式必须从行首开始；日志行首是时间戳，所以命中 120 行

$ 行尾

模式必须到行尾结束；requests$ 只命中 1 行

^ERROR

要求 ERROR 出现在行首；本日志行首是日期，因此 0 行

整行限定

^...$ 表示整行都符合模式，常用于格式校验

^ 放在方括号内表示“排除”，如 [^0-9]；放在方括号外才是行首锚点。
Linux 实验11｜正则表达式07

字符集合 [ ]：任意一个备选字符

方括号里列出候选，匹配其中任意一个字符

grep -E 'thread=worker-[12]' app.log | wc -l
grep -E '\[[Ee]rror\]' app.log | wc -l

匹配什么

[12] 匹配字符 1 或字符 2，只占一个位置

能匹配

worker-1、worker-2，共 60 行

不能匹配

worker-3、worker-4；[12] 也不匹配字符串 “12” 整体

范围写法

[0-9]、[a-z]、[A-Fa-f0-9]

[Ee]rror 同时覆盖 Error 与 error，共 20 行。注意日志里级别带方括号，模式中要写 \[ 和 \]。
Linux 实验11｜正则表达式08

排除集合 [^ ]：不是这些字符

方括号内第一个位置写 ^，表示“除了列出的字符以外”

grep -E 'Class[^1]' scores.csv | wc -l

匹配什么

任意一个不在集合中的字符，仍然只占一个位置

能匹配

[^0-9] 匹配 a、-、空格；[^1] 匹配 2、3

不能匹配

[^0-9] 不匹配 5；也不能匹配“空”

本课结果

Class[^1] 命中 Class2、Class3，共 19 行

[^...] 要求该位置必须有一个字符。要表达“整行都不含某内容”，用 grep -v 更直接。
Linux 实验11｜正则表达式09

量词 *：前一项出现 0 次或多次

星号修饰它左边的那一个字符或那一组

匹配什么

左边的项可以不出现，也可以连续出现很多次

能匹配

ab*c 匹配 ac、abc、abbbc

不能匹配

ab*c 不匹配 ad；结尾必须是 c，abbd 也不行

常见组合

.* 表示“任意长度的任意内容”

grep -E '^[0-9]*$' app.log | wc -l
grep -E 'ERROR.*attempts' app.log | wc -l
第一条结果为 0 行：允许零个数字，但整行仍必须只由数字组成；第二条结果为 1 行，中间由 .* 跨过。
Linux 实验11｜正则表达式10

量词 +：前一项出现 1 次或多次

与 * 的区别：+ 至少要求出现一次

grep -Eo 'pid=[0-9]+' app.log | wc -l
grep -E 'thread=worker-[0-9]+' app.log | wc -l

ab+c

匹配 abc、abbbc；不匹配 ac

ab*c

匹配 ac、abc、abbbc

本课结果

每行都有 pid 和 worker 编号，两个模式各命中 120 次

使用建议

知道“至少有一个数字”时优先用 +，语义更准确

量词只修饰紧挨着它左边的一项：[0-9]+ 是“一串数字”，[0-9]+[0-9] 仍是“至少两位数字”。
Linux 实验11｜正则表达式11

量词 ? 与 {n,m}：精确控制次数

用区间写法描述“几位数字”“几年几月几日”

grep -E '^[0-9]{4}-[0-9]{2}-[0-9]{2}' app.log | wc -l
grep -Eo 'req-[0-9]{4}' app.log | head -3

?

0 次或 1 次；colou?r 匹配 color 与 colour，不匹配 colouur

{n}

恰好 n 次；[0-9]{4} 恰好四位数字

{n,}

至少 n 次；[0-9]{2,} 两位及以上数字

{n,m}

n 到 m 次；[0-9]{2,3} 两到三位数字

本课结果：120 行全部以“四位年-两位月-两位日”开头；request_id 依次为 req-0001、req-0002、req-0003。
在 grep 的基础正则中，? 与 { } 需要写成 \?、\{n,m\}；加 -E 后可直接书写。
Linux 实验11｜正则表达式12

字符类：\d、\w、\s 与 POSIX 写法

它们是对常见字符集合的简写，但不同工具的识别情况不一样

\d

一个数字 0–9，等价 [0-9]、[[:digit:]]

\w

字母、数字、下划线，等价 [A-Za-z0-9_]、[[:alnum:]_]

\s

一个空白字符（空格、制表符等），等价 [[:space:]]

POSIX 类

[[:digit:]]、[[:alpha:]]、[[:alnum:]]、[[:upper:]]、[[:lower:]]

grep -Eo '[[:digit:]]{4}' app.log | head -3
grep -Eo '[[:alpha:]]{4,}' app.log | head -3
实测注意：GNU grep -E 不识别 \d，请写 [0-9] 或 [[:digit:]]；\w、\s 属于 GNU 扩展，换工具时优先用 POSIX 类。
Python、JavaScript 等语言的字符串正则中，\d、\w、\s 是标准写法，记住对应关系即可。
Linux 实验11｜正则表达式13

grep -E 的常用选项

模式写好后，用选项控制“输出什么”和“怎么匹配”

grep -Eo 'pid=[0-9]+' app.log | head -3
grep -Ew 'pid=2100' app.log | wc -l
grep -Eic '\[error\]' app.log

-E

启用扩展正则，直接使用 + ? { } ( ) |

-o

只输出匹配到的那一段，用于提取字段

-w

整词匹配，避免把更长的编号算进来；本课结果 8 行

-i / -c

忽略大小写并直接输出匹配行数，结果为 30

-c 已经完成计数；grep -E ... | wc -l 也会得到同样的数字，只是多经过一次管道。

实战：用 -o 提取三类字段

日志每行结构固定，可以分别提取时间戳、进程号和请求号

grep -Eo '^[0-9]{4}-[0-9]{2}-[0-9]{2} [0-9]{2}:[0-9]{2}:[0-9]{2}' app.log | head -3
grep -Eo 'pid=[0-9]+' app.log | head -3
grep -Eo 'request_id=req-[0-9]{4}' app.log | head -3

时间戳

每行一个，共 120 条，格式 2026-11-06 08:00:00

pid

共 120 个，去重后是 17 个不同进程号

request_id

共 120 条，从 req-0001 到 req-0120

提取思路

先写模式，再用 -o 只留下匹配片段

去重统计：grep -Eo 'pid=[0-9]+' app.log | sort -u | wc -l 输出 17。
Linux 实验11｜正则表达式15

实战：ERROR 行的三种写法与计数

grep -E '\[ERROR\]' app.log | wc -l
grep -E '\[ERROR\]|\[Error\]' app.log | wc -l
grep -Ei '\[error\]' app.log | wc -l

只写大写

10 行，漏掉 Error 与 error

用“或”写两种

20 行，仍漏掉全小写

忽略大小写

30 行，三种写法全部覆盖

级别分布

INFO 40、WARN 20、NOTICE 20、DEBUG 10

正则默认区分大小写；当“大小写只是格式差异”时，用 -i 比写三套模式更稳妥。
Linux 实验11｜正则表达式16

sed 中的正则：替换与按模式打印

sed 逐行读取文本，正则用于“找什么”和“替换什么”

sed -E 's/[0-9]{4}-[0-9]{2}-[0-9]{2}/DATE/' app.log | head -4
sed -nE '/^2026-11-06 09:/p' app.log | wc -l
sed -nE '/\[ERROR\]/p' app.log | wc -l

s/正则/替换/

把匹配到的部分换成新文本；第一行开头变为 DATE 08:00:00 ...

-n + /正则/p

只打印匹配行；9 点日志共 20 行

ERROR 行

/\[ERROR\]/p 输出 10 行

默认行为

不加 -n 时 sed 会输出所有行，容易看错结果

s/// 默认只替换每行第一个匹配；加 g 才会替换全部。分组与 \1 反向引用属于拓展内容，本课只需知道有这个能力。
sed 不加 -i 时只改变屏幕输出，不会修改 app.log。
Linux 实验11｜正则表达式17

awk 中的正则：整行匹配与字段匹配

awk 默认按空白分列：$1 日期、$2 时间、$3 级别、$4 pid

awk '/^2026-11-06 08:/ {n++} END {print n}' app.log
awk '$3 ~ /\[ERROR\]/ {print $1, $2, $4}' app.log | head -3
awk '$3 ~ /\[[Ee][Rr][Rr][Oo][Rr]\]/ {n++} END {print n}' app.log

/正则/

匹配整行，相当于对 $0 判断；8 点共 19 行

$3 ~ /正则/

只检查第 3 个字段；可输出日期、时间与 pid

!~

字段不匹配时才为真，用于排除某类记录

大小写覆盖

逐字母写字符类，ERROR、Error、error 合计 30 行

awk 的字段从 1 开始编号，$0 表示整行；~ 是“匹配”，!~ 是“不匹配”。

常见问题：先检查引号与转义

grep -E 没有任何输出

可能大小写不一致、模式多写了空格，或把普通字符写成了元字符。先用 -o 看匹配片段。

+ ? { } 不生效

忘记加 -E 时，这些符号按普通字符处理；基础正则中要写 \+、\?、\{n,m\}。

[ 未闭合或空匹配

[abc 缺少右括号；[] 不是“空集合”。把 ] 放首位、- 放首尾可表示字面量。

\d 被当成字母 d

GNU grep -E 不识别 \d；改用 [0-9] 或 [[:digit:]]。

排错顺序：确认文件与路径 → 检查引号与转义 → 检查大小写 → 用 grep -Eo 观察实际匹配 → 再统计。
模式写在单引号里最安全，可避免 shell 把 $、|、* 先解释掉。
