grep -i：忽略大小写

搜索时不区分 ERROR、Error、error

区分大小写

grep "error" app.log

仅匹配小写 error

忽略大小写

grep -i "error" app.log

匹配 ERROR / Error / error

观察

比较两次输出行数与内容差异

尝试

把关键词换成 INFO，再对比一次

-i 只影响匹配规则，不修改原文件。
Linux 实验5｜文本搜索与统计09

grep -n：显示行号

搜索结果前增加原文件中的行号

grep -n "ERROR" app.log
grep -in "error" app.log

阅读结果

例如 2:ERROR Disk full 中，2 表示原文件第 2 行。

组合选项

-i 与 -n 可合用；-in 等价于 -i -n。

行号便于在日志与配置文件中快速定位。

grep -v：反向筛选

显示不匹配指定模式的行

正向搜索

grep "INFO" app.log

保留匹配的行

反向筛选

grep -v "INFO" app.log

保留不匹配的行

组合选项

grep -iv "error" app.log

先忽略大小写，再排除

思考

上述命令各输出多少行？为何保留这些行？

结论：-v 表示反向选择。
Linux 实验5｜文本搜索与统计11

grep -w：整词匹配

只匹配完整单词，避免匹配到单词的一部分

普通搜索

grep "error" app.log

可能匹配 terror、errorcode 等子串

整词匹配

grep -w "error" app.log

只匹配独立的 error 单词

组合

grep -iw "error" app.log

忽略大小写 + 整词

思考

两次输出行数是否不同？多出来的行含什么？

-w 让匹配更精确，适合查找独立关键词。
Linux 实验5｜文本搜索与统计12

grep -A / -B / -C：显示上下文

在匹配行之外，额外显示前后若干行，便于理解日志语境

-A after

grep -A 2 "ERROR" app.log

匹配行 + 后面 2 行

-B before

grep -B 2 "ERROR" app.log

匹配行 + 前面 2 行

-C context

grep -C 2 "ERROR" app.log

匹配行 + 前后各 2 行

可与 -n / -i 合用，例如 grep -nC 1 -i "error" app.log
-C n 等价于同时使用 -A n 与 -B n。
Linux 实验5｜文本搜索与统计13

grep -c：统计匹配行数

不列出匹配行，只输出每个文件的匹配行数

grep -c "ERROR" app.log
grep -ci "error" app.log

grep -c

直接给出匹配行计数；默认不打印行内容。

与管道对比

grep … | wc -l 也能计数；-c 更短，且按文件分别统计。

注意：-c 统计的是匹配行数，不是匹配次数（一行多次出现仍计 1）。
Linux 实验5｜文本搜索与统计14

grep -l / -L：列出文件名

只关心“哪个文件命中 / 未命中”，不输出匹配行内容

-l 有匹配

grep -l "ERROR" *.log

列出至少含有 ERROR 的文件名

-L 无匹配

grep -L "ERROR" *.log

列出不含 ERROR 的文件名

典型场景

在多个日志中快速筛选“出过错的文件”

提示

当前练习以 app.log 为主；多文件时 -l/-L 更有用

-l 与 -L 互为相反：一个列“有”，一个列“没有”。
Linux 实验5｜文本搜索与统计15

grep -E：扩展正则表达式

启用 ERE，可用 |、()、+、? 等更灵活的模式

grep -E "ERROR|WARN" app.log
grep -Ei "error|warn" app.log

交替匹配

ERROR|WARN：匹配 ERROR 或 WARN

为何用 -E

普通 grep 中 | 需写成 \|；-E 写法更直观

等价命令

egrep 常等价于 grep -E（推荐写 grep -E）

尝试

用一条命令同时找出 ERROR 与 INFO

先掌握字面关键词，再逐步使用正则；模式请放在引号中。
Linux 实验5｜文本搜索与统计16

grep -r / -d：目录与递归搜索

在目录树中搜索，或指定遇到目录时的处理方式

-r 递归

grep -r "ERROR" LogLab

进入目录及其子目录搜索所有文件

-d 目录行为

grep -d skip "ERROR" LogLab

skip：跳过目录；recurse：递归（类似 -r）

常用组合

grep -rn "ERROR" LogLab

递归 + 显示行号

注意

对单个文件搜索时一般不需要 -r；对目录才需要

-r 适合在工程或日志目录中“一把搜”；-d 精确控制目录处理。
Linux 实验5｜文本搜索与统计17

wc -l：统计行数

wc 是统计命令，-l 表示统计换行符的数量

wc -l app.log
cat app.log | wc -l

直接统计文件

显示计数，并附带文件名。

管道统计

统计管道收到的行，通常只显示数字。

对比：grep -c 统计匹配行；wc -l 统计输入总行数。
Linux 实验5｜文本搜索与统计18

认识管道符 |

把左边命令的标准输出交给右边命令继续处理

grep 命令
grep -i "error" app.log
|
wc -l
统计行数
=
匹配行数

grep 先输出匹配的日志行，wc -l 接收这些行并统计数量。管道不修改文件。

常用组合：grep … | wc -l；也可直接用 grep -c。

常见报错：先检查命令和文件

grep: 找不到 app.log

用 pwd / ls 确认当前目录与文件是否存在

grep 无输出

可能未匹配、大小写问题，或 -w 过严

wc: invalid option

误把 -l 写成 -1（数字一）

管道 / 正则不对

检查引号、关键词；-E 模式中的 | 是否正确

排错顺序：检查位置 → 检查文件 → 检查关键词和选项 → 再运行验证。
