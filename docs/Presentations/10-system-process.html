程序与进程：先分清两个概念

程序是文件，进程是运行中的实例

程序

  • 存放在磁盘上的可执行文件
  • 本身是静态的，不占用 CPU
  • 同一个程序可以启动多次

进程

  • 程序运行时的实例
  • 占用 CPU、内存等资源
  • 每个进程有独立的 PID
PID（Process ID）是进程标识号，查看和结束指定进程时都会用到。
进程状态会随程序运行而变化，命令输出以终端当前显示为准。

ps：查看当前进程

ps 可以显示进程 ID、终端、状态和启动命令

ps
ps -ef
ps aux

ps

显示当前终端关联的进程，适合快速查看。

ps -ef

显示完整进程列表，标准格式，常用于查找指定程序。

ps aux

显示完整进程列表，另一种常见详细格式。

ps 显示的是执行命令那一刻的进程快照，不会自动刷新。

读懂 ps 输出，并用 grep 定位

先找 PID 和 CMD，再决定下一步操作

ps -ef | head
ps -ef | grep bash
ps aux | head

常见字段

UID 用户、PID 进程号、PPID 父进程号、TTY 终端、TIME 占用时间、CMD 启动命令。

用 grep 定位

按程序名筛选进程行；搜索结果中可能包含 grep 自身，需要会区分。

进程列表较长时，用 | head 先看前几行，再用 grep 搜索程序名。

top：动态观察进程

持续刷新进程与资源使用情况

top

动态刷新

持续更新 CPU、内存和进程列表。

按 P

按 CPU 使用率排序。

按 M

按内存使用率排序。

top 是交互式界面；先看 CPU、MEM、PID、COMMAND，不要求一次读懂每一列。

pgrep：按进程名查找 PID

不确定 PID 时，先按名称查

pgrep sleep
pgrep -l bash
ps -ef | grep '[s]leep'

pgrep 名称

直接输出匹配进程的 PID。

pgrep -l

同时显示进程名，便于确认。

ps | grep

输出信息更完整，但需要自己挑出 PID。

结束进程前先确认 PID，避免结束别人的进程或系统进程。

kill 与 kill -9 的区别

先正常结束，必要时才强制结束

kill PID（默认 -15）

发送 SIGTERM，请求进程正常结束，程序有机会进行清理。

kill -9 PID

发送 SIGKILL，强制结束进程，进程无法自行处理清理操作。

先确认目标

ps -p PID

确认 PID 对应的确实是自己的测试进程。

使用原则

优先使用默认 kill 或 -15；-9 只在必要时使用。

不要随意结束系统进程或别人的进程；kill 发送的是信号，不是“删除”。

安全演示：启动、查找、结束

只操作自己启动的 sleep 测试进程

sleep 300 &
PID=$!
echo $PID
ps -p $PID
kill $PID
ps -p $PID

命令说明

sleep 300 & 在后台启动测试进程；$! 是最近一个后台进程的 PID。

验证结果

kill 后再次执行 ps -p $PID，没有进程信息即表示已经结束。

把 PID 换成自己终端里真实出现的数字，不要照抄示例。

free：查看内存使用情况

使用 -h 以易读单位显示内存信息

free
free -h
free -h -s 2

Mem

查看物理内存总量、已使用和可用情况。

Swap

查看交换空间，未配置时可能为 0。

-h

用 MB、GB 等易读单位显示。

-s 2

每 2 秒刷新一次，按 Ctrl+C 结束。

已用内存含缓存；判断内存是否紧张，重点看可用空间。

df -h：查看文件系统空间

看各挂载点的总容量、已用空间和可用空间

df -h
df -h /home

df -h

列出各文件系统的容量、已用、可用和挂载点，单位易读。

重点关注

Use% 使用比例与 Available 可用空间；某个挂载点接近 100% 时要及时处理。

df 看的是文件系统整体，不会列出某个目录内部每个文件占多少。

du -sh：查看目录占用

du 统计目录或文件实际占用的空间

du -sh /home/njucm
du -sh ~/Desktop
du -sh *

-s

只显示总计，不展开每个子目录。

-h

以易读单位显示大小。

*

比较当前目录下各对象的大小。

df 看文件系统整体空间，du 看目录或文件占用，两者统计范围不同，结果可能不一致。

常见问题：先检查命令和操作对象

ps 中找不到目标进程

进程可能已经结束，或搜索关键词不正确；重新启动测试进程并检查 PID。

kill: No such process

PID 可能输入错误或进程已经退出；使用 ps -p PID 重新确认。

top 无法退出

在 top 界面按 q；不要把 Ctrl+C 当作唯一退出方式。

df 与 du 结果不同

df 统计文件系统空间，du 统计目录或文件占用，两者范围不同。

排错顺序：确认命令 → 确认 PID 或路径 → 查看输出 → 再次验证。
