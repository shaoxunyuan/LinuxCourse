场景问题：权限到底在判断什么？

Linux 每次访问文件或目录，都要把“身份”和“对象权限”对应起来

① 当前用户是谁？

whoami / id / groups
先确认 njucm 属于哪些组

② 对象属于谁？

ls -l 文件
关注所有者 owner 与所属组 group

③ 权限允许什么？

r = read
w = write
x = execute / enter

-rwxr-xr-- 1 njucm njucm 128 Oct 12  run.sh
判断权限不要只看 rwx，还要结合当前用户、文件所有者和所属组。

Linux 实验4｜用户、用户组与权限05

概念讲解：读懂 ls -l 权限字符串

先分成三组三位：owner｜group｜others，再分别读 r、w、x

-rw-r--r-- 1 njucm njucm 24 demo.txt

第 1 位

- 普通文件 · d 目录

第 2～4 位

owner 权限，如 rw-

第 5～7 位

group 权限，如 r--

第 8～10 位

others 权限，如 r--

例：-rw-r--r-- 表示所有者可读写，同组和其他用户只能读。
Linux 实验4｜用户、用户组与权限06

概念讲解：r、w、x 对文件和目录含义不同

r：read

文件：可以读取文件内容
目录：可以列出目录中的名称，能否进入还要看 x

w：write

文件：可以修改文件内容
目录：可以创建、删除或重命名条目，通常需要 x 配合

x：execute / enter

文件：允许作为程序执行
目录：允许进入目录并访问其中已知名称的对象

目录权限最容易混淆：对目录来说，x 表示“可进入 / 可穿越”。

概念讲解：所有者、用户组与 sudo

chown

修改文件所有者
示例：chown user file
通常需要管理员权限

chgrp

修改文件所属组
示例：chgrp group file

sudo

临时以管理员权限执行命令
课程中只在明确需要时使用

最小权限原则：能用当前用户权限解决的问题，不要先加 sudo；能只加 u+x，就不要把文件改成 777。
权限只给“完成任务刚好够用”的程度。

Linux 实验4｜用户、用户组与权限10

命令演示：chmod 符号法

先说清楚“给谁改什么”

chmod u+x run.sh
ls -l run.sh
chmod o-r secret.txt
ls -l secret.txt
chmod g-w public.txt
ls -l public.txt

对象

u = user
g = group
o = others
a = all

动作

+ 增加
- 删除
= 直接设置

例

u+x：给所有者增加执行权限

修改后立即使用 ls -l 验证。符号法适合“只改一小部分权限”。
Linux 实验4｜用户、用户组与权限11

命令演示：chmod 数字法

r = 4，w = 2，x = 1，相加得到三位数字

644

自己可读写，其他只读

600

只有自己可读写

755

自己可写并执行，其他可读执行

700

只有自己拥有全部权限

chmod 644 file.txt
chmod 600 secret.txt
chmod 755 run.sh
chmod 700 private_dir
不要把 chmod 777 当成“修复权限”的默认做法。

练习5：制造并解决 Permission denied

printf '#!/bin/bash\necho Hello Permission\n' > run.sh
chmod 644 run.sh
./run.sh
ls -l run.sh
chmod u+x run.sh
./run.sh

第一次运行

预期看到 Permission denied，因为脚本没有执行权限。

定位原因

先用 ls -l 检查是否缺少 x，不要直接 sudo。

修复

只增加 owner 的执行权限，再运行验证。

常见问题：先看报错在说什么

Permission denied

当前身份缺少所需 r、w 或 x。先用 id、ls -l 判断，不要立刻 sudo。

Operation not permitted

可能不是文件所有者，或没有修改权限。先确认 owner，再决定下一步。

chmod: cannot access ...

路径或文件名写错。使用 pwd、ls 检查当前位置和对象是否存在。

chmod 777 后虽然能用了

权限过大，不代表设置合理。按实际需求改成 600、644、700、755 等。

排错顺序：读报错 → pwd / ls 确认对象 → id / ls -l 检查身份与权限 → 做最小修改 → 再次验证。
